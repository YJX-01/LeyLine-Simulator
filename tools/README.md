# Development tooling

`scripts/` contains repository automation; `patches/` contains committed dependency fixes. Invoke normal tasks through root `pnpm` scripts, which work independently of the script directory depth.

- `pnpm architecture:check`: workspace dependency and directory rules.
- `pnpm data:check`, `pnpm fixture:check`: generated-data consistency.
- `pnpm build:check`, `pnpm perf:engine`: build and simulation budgets.
- `pnpm preview`: serve `src/web/dist/` locally.
- `pnpm release:prepare`, `pnpm release:verify --dir=<candidate>`: local delivery; see [deployment](../docs/deployment.md).

## Dependency maintenance

Run `pnpm install --frozen-lockfile` at the repository root. `pnpm-workspace.yaml` discovers `src/*`, places the content store in `.cache/pnpm-store`, and applies `tools/patches/`. Root and workspace-local `node_modules/` directories are generated by pnpm's isolated dependency layout. Do not commit, manually merge, or relocate them. Workspace package names and public imports remain `@leyline/*` when source paths change.

## Cleanup

- `pnpm clean:outputs --dry-run`: list existing generated outputs that would be removed.
- `pnpm clean:outputs`: remove build outputs, browser traces, coverage, reports, and local release candidates under `artifacts/`. Save any candidate you want to retain outside that directory first.
- `pnpm clean:cache`: remove `.cache/`, including the pnpm download store and temporary patch edits. Installed `node_modules/` remains usable; subsequent installation may download packages again. Finish and commit any intentional dependency patch before clearing this cache.

The cleaner uses fixed repository-local paths and refuses directory links or tracked content. It keeps source, documentation, the Python archive, GitHub workflows, configuration, and installed dependencies. Build/test commands recreate their outputs when needed. After `pnpm clean:outputs`, rebuild before using preview or production tests, and rerun both browser suites before preparing a release.

For deliberate dependency patches:

```sh
pnpm patch @vue/devtools-kit@8.2.1 --edit-dir .cache/patch-work/devtools-kit
# Edit only the extracted dependency, then:
pnpm patch-commit .cache/patch-work/devtools-kit --patches-dir tools/patches
```

Commit the patch, workspace configuration, and lockfile together. Keep temporary edits in `.cache/patch-work/`; the former `.patch-work/` root directory is retired. Verify frozen installation and browser storage-recovery tests after patch changes. See [the current patch rationale](patches/README.md).

## Paths and release portability

Scripts compute the repository root from their own URL, two levels above `tools/scripts/`. The release copy keeps the same `tools/scripts/serve-dist.mjs` depth, so `node tools/scripts/serve-dist.mjs --dir=site` works inside a standalone candidate without this checkout or dependencies.
