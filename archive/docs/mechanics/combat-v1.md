# combat-core-v1：阶段3机制合同

状态：首批规则通过阶段3验收。它是单目标、手动面板的通用机制配置，不是当前全部游戏内容的完整实现。真实角色的倍率、附着标签、快照例外、产球和命中行为必须在阶段4逐项接入。

## 入口与兼容

引擎入口 `simulateCombat(unknown)`；schemaVersion=1，rulesVersion=combat-core-v1。场景、技能和指令都是经过 Zod 校验的数据，不执行用户脚本。允许1—4个测试面板，技能必须引用存在的所有者，指令必须引用存在的技能/角色；集合 ID 唯一。旧的单次攻击、人工动作和琴点按验证入口保留。

配置中技能直接提供倍率和效果，故 dataVersion 标记 synthetic-mechanics-v1；不要用测试技能冒充真实角色或完整四人配队。角色基础攻击、武器攻击、等级等为手动输入，不推断等级成长和装备效果。

## 时间与状态

整数毫秒，模拟窗口包含终点。增益、减益、召唤物持续区间都是[开始,到期)，不存在终点额外一跳。静态预置事件优先级：到期-30、增益/减益开始-20、回能到达-10、命中0、指令10；同类按输入顺序。回调产生的新事件只能在原因事件之后执行，即使它设置了更早的优先级。

同刻预置回能先于切人，因此该时刻的预置粒子以前一前台身份结算。零旅行时间的新粒子在造成它的命中之后到达。切人和施放共用动作锁，切人有1000ms冷却。失败记录原因，不刷新任何冷却或消耗能量。技能冷却时间为施放时间+开始延迟+冷却；恰好到期可再次施放。

每次调用独立创建调度、增益、能量、附着、随机和召唤物状态。尚无动作取消、受击、冲刺、跳跃、多目标、生命与护盾系统。

## 增益、快照与敌人

支持攻击加成、固定攻击、伤害加成、暴击、精通、充能、反应加成等非负增益；同组 add 独立叠加，replace 只与同目标同组的 replace 互斥。新效果替换旧值并重置到期时间；旧效果到期回调不能移除新效果，旧效果也不会在新效果到期后复活。

snapshot=true 在施放时保存面板；false 在每次命中时读取面板。directDamageBonus 在命中时读取，永不随面板快照保存。敌人减抗、减防同样在命中时读取。快照范围是本合同定义的规则，不自动等同任何真实角色的全部快照细节。[快照与动态依据](https://library.keqingmains.com/combat-mechanics/snapshot-and-dynamic)

敌人可提供统一有效抗性，或为火/水/冰/物理单独覆盖抗性。减抗相加；减防相加后最多100%，再与无视防御相乘。伤害保留基础、加成、暴击、防御、抗性和反应乘区；命中日志区分快照增益和当前直接伤害增益。

## 能量

同色/异色/无色粒子系数分别3/1/2，晶球为粒子的3倍；前台系数1，后台为1-0.1×队伍人数。粒子和晶球乘接收时的角色充能；固定回复不乘充能。能量限制在容量内，日志记录实际回复与溢出。成功施放消耗指定数值，不会自动清空所有能量。[能量依据](https://library.keqingmains.com/combat-mechanics/energy)

技能 particlesOnHit 在命中时生成粒子，支持数量、旅行时间与独立产球冷却，未命中或施放失败不产球。旅行超出窗口则不结算。外部 pickups 用于敌人掉落或显式环境回能。数量是配置值，不隐式猜测角色概率产球；角色特例留给内容适配。

## 召唤物

周期召唤物按 firstDelayMs 后每隔 intervalMs 命中；协同召唤物仅响应友方直接命中，遵守独立冷却和触发延迟，召唤物伤害不能递归触发协同召唤物。所有伤害归属创建者，切人不销毁召唤物。

每个(所有者,槽位)最多一个实例，新实例替换旧实例，旧定时回调失效。持续时间从创建时刻开始；面板快照仍按施放时刻捕获。延迟协同命中若晚于到期或替换则取消；允许不同槽位共存。触发目标筛选、受击破坏等特殊召唤物行为尚不支持。

## 附着与首批反应

ICD 按(施加者,标签)隔离，单目标隐含在本合同中。标准规则第1/4/7次可附着，2.5秒计时到期重置计数；计数触发不重置计时。none 每次可附着。ICD只阻止附着/反应，不阻止基础伤害。[ICD依据](https://library.keqingmains.com/combat-mechanics/internal-cooldown)

支持火、水、冰单一附着，1/2/4U来源落地乘0.8；初始寿命9.5/12/17秒，线性衰减。同色刷新取较大剩余量，保持初始衰减率；火附着刷新若提高元素量则更新衰减率。衰减在命中及窗口终点惰性计算，不单独输出自然衰减事件。[元素量依据](https://library.keqingmains.com/combat-mechanics/elemental-effects/elemental-gauge-theory)

水打火蒸发、火打冰融化为2倍并消耗触发量×2；火打水、冰打火为1.5倍并消耗触发量×0.5。反应额外乘(1+2.78×精通/(1400+精通)+反应加成)。反应耗尽后不把溢出的触发元素重新挂到目标。[增幅反应依据](https://library.keqingmains.com/combat-mechanics/elemental-effects/amplifying-reactions)

水冰相遇会明确失败，不能用“无反应”掩盖缺失的冻结语义。电/风/岩/草攻击、剧变反应、共存附着、元素护盾与角色特殊附着不在本阶段首批支持范围。能量接收者可以使用七元素，攻击来源只允许火/水/冰/物理。

## 随机与资源界限

所有配置显式传 uint32 种子。random 使用本地 Mulberry32，每次实际命中消耗一个暴击随机数；期望和强制模式不抽样。没有承诺与 Python 随机序列或游戏随机序列一致。

限制：时长1小时、角色4、技能64、指令2000、角色增益1000、敌人减益1000、外部回能2000。单次最多执行20000个调度回调，超限整次失败。详细日志最多20000条并可配置更低上限，超限明确报错，不返回看似完整的截断结果。summary 不保存逐事件日志，但保留伤害、能量、反应次数和事件统计。浏览器日志按50条分页。

## 综合人工算例

`fixtures/scenarios/combat-stage-3.json`：4秒窗口，所有面板基础攻击1000，敌人无抗性且防御完全无视。火召唤物在50%攻击增益中施放，保存1500攻击；增益于1000ms结束。1500—2000ms有20%直接伤害加成。首次召唤命中生成2颗火粒子，700ms后到达；产球冷却保证窗口内只生成一次。

| 时间ms | 事件 | 人工伤害 |
| --- | --- | --- |
| 500 | 火召唤命中并附着 | 1500 |
| 1000 | 切水，水命中触发蒸发 | 1000×2=2000 |
| 1500 | 火召唤保留快照，动态直接加成 | 1500×1.2=1800 |
| 2000 | 切火消耗6能量，物理命中 | 1000 |
| 2500 | 火召唤仍保留快照 | 1500 |
| 3000 | 召唤到期，切冰触发反向融化 | 1000×1.5=1500 |

总伤害9300，DPS2325。火个人伤害5800、水2000、冰1500。取消快照后总伤害8200。

1200ms粒子到达，水在前台：后台火以200%充能获得2×3×0.6×2=7.2，容量6故溢出1.2；水获得2，冰与风各1.2。1300ms水固定回复5，最终水7。2000ms火消耗6，最终火0。最终冰与风各1.2。预期文件是以上独立人工计算，不能自动用引擎结果回填。
