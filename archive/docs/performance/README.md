# 性能基线

F0已将本页引用的四份历史JSON记录原样移到`fixtures/performance/history/`；`docs/`只保留说明。下文数值和测量边界是历史记录，不作为后续真实案例验收。

执行 `pnpm perf:engine`，默认报告写入忽略的 `artifacts/performance/engine.json`。显式 `--output=路径` 可保存待审核的基线；不要将每次运行结果覆盖为新的门槛。

`stage-6-engine-baseline.json` 为本机首次测量，记录Node/CPU/内存、源码提交和方法。各场景预热2次、测量7次；其中p95按七次最大值保守报告，不代表充分采样的总体分位数。GC前后十次丢弃结果的堆差值只用于发现明显滞留，不是浏览器内存或无泄漏证明。首次Vite加载/编译不计入纯引擎耗时。

场景由 `fixtures/performance/scenarios.ts` 统一生成：48秒已验收四人循环、重复十次的480秒压力循环、2000条琴普攻的详细/摘要模式。480秒场景不是经审核的能量闭环，存在拒绝指令，其目的仅为持续状态压力。

初始预算：引擎七次最大值2秒、单份结果序列化8MB、十轮GC后额外堆32MB；预算为跨开发机/CI的宽容回归门槛，不是本机典型耗时。浏览器单独验证结果与图表10秒、筛选加翻页2秒、取消界面反馈1秒，包含Playwright驱动往返。取消用延迟Worker加载保证可重复，任务迟到消息隔离由单元测试验证。

浏览器压力用例每次输出 `browser-performance.json` 附件，确保2000条动作后日志只渲染40条，并能连续运行和取消。真实性能趋势需在相同硬件、相同浏览器、相同负载下比较，不能把跨机器差异直接归因为代码回归。

阶段6最终复测见 `stage-6-engine-final.json`、`stage-6-browsers.json`，分包与构建预算见 `stage-6-build.json`。最终2000条动作的引擎中位数17.30ms、七次最慢21.88ms，十轮GC后堆差-355432字节；负数属于GC/测量波动，不能解读为代码主动回收了固定数量的内存。

| 浏览器 | 结果与图表（ms） | 筛选加翻页（ms） | 取消界面反馈（ms） |
| --- | --- | --- | --- |
| Chromium | 496 | 125 | 52 |
| Firefox | 657 | 201 | 84 |
| WebKit | 603 | 248 | 171 |

以上为本机最终矩阵中的单次浏览器测量，不是分位数。页面与开发服务已经初始化，计时从点击计算前到结果和图表就绪，不能解释为从空缓存网络首次访问的完整加载时间。功能等待采用10秒上限以覆盖Windows WebKit冷启动，独立性能断言仍维持原预算，未通过自动重试掩盖失败。
## P3 属性与历史图基准

执行 `node tests/performance/timeline.mjs`，报告写入本地 `artifacts/performance/workbench-p3.json`。基准从生产契约样本构造500个属性捕获命中和500个前序伤害加结算；独立目标分别3450000和25000。一轮预热、七轮测量，p95按最大值报告，包含schema解析、依赖求值和轨迹构造，不含Vite启动。

新图单场景门槛为2秒和结果序列化8MB；不修改旧模拟器或构建预算。另验证真正含自身的历史循环、128层深度保护和1000命中×200效果的100000访问预算终止。确定性求值器用访问预算停止，性能脚本用运行时间检查回归；不将旧模拟器吞吐当作历史图性能。
