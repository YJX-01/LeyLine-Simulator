# TypeScript 重写实施计划

## 目标与范围

统一采用 Vue 3、TypeScript 和 Vite，独立模拟引擎运行于 Web Worker。旧 Python 项目保留为参考和结果对照，最终产品不依赖 Python。首先保证计算可解释、可复现，再扩展内容和界面。

第一版：四人配队、等级/天赋/命座/装备配置、结构化动作序列、固定时长模拟、伤害/DPS/能量/事件展示、本地方案保存和 JSON 导入导出。首批候选角色为雷电将军、行秋、胡桃、阿贝多、琴，逐项验证后声明支持。第一版不包括全角色、自动配装、账号云同步和桌面打包。机制必须注明规则版本，不能默认旧代码符合当前游戏。

## 工程结构

- src/web：Vue 页面、Worker 接入，后续使用 Pinia 管理编辑状态、ECharts 展示结果。
- src/schema：Zod 输入输出校验、配置版本与迁移。
- src/engine：独立 TS 引擎，不依赖 Vue、DOM 或图表。
- src/game-data：经过核实的静态数据与有类型的技能模块。
- fixtures/scenarios、fixtures/expected：标准输入和审核后的预期结果。
- docs/architecture、docs/mechanics：设计决策、机制依据及限制。

使用 pnpm workspace；Vitest 验证核心，Playwright 验证浏览器流程。测试数据不能冒充经过核实的游戏内容。

## 引擎约束

1. 每次模拟独立持有状态，禁止共享可变单例。
2. 时间使用整数单位；实现调度前确定精度。同刻事件以优先级和序号稳定排序，明确到期与命中的顺序。
3. 期望与随机模式分离；随机模式显式种子。结果记录配置、引擎、规则和数据版本。
4. 静态倍率与技能逻辑分离；显式注册技能，不使用 eval/exec 或执行用户代码。
5. 引擎只接收结构化动作；文本指令兼容由单独解析器完成。
6. 伤害日志保留结算明细，后续提供摘要/详细模式和输出规模限制。
7. Worker 协议包含任务标识，防止旧任务结果覆盖新任务；取消和异常后可重新运行。

## 正确性验证

公式用例采用人工可核算数据；机制用例覆盖时间边界、附着、能量、快照、后台技能；队伍场景固定配置和随机种子。旧 Python 结果是对照而非唯一真值。差异定位到第一个事件，记录旧缺陷、新缺陷或规则变更。事件次数和顺序精确比较，数值明确容差。验证非法输入、不支持内容、连续任务、取消、导入及 Worker 恢复。

## 迁移与切换

保留 src/ 和现有 docs/，新代码进入 apps/、packages/。旧 JSON 必须审计字段、单位、来源和版本后转换。首批内容验收、完整四人场景审核、差异记录、方案存储与恢复通过后，才将新版作为正式默认入口。
