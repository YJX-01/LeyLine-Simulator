# 内容、格式与精度

正式内容采用严格 JSON，使用 UTF-8 无 BOM、LF、两空格缩进和一个末尾换行。数值须有限，标识稳定，有意义的数组顺序保持。原始采集证据保留来源字节，运行投影由正式输入确定性生成。

## 共同内容模型

同一种实体使用共同契约。内置与自定义角色共用身份、文本、成长、天赋参数与命中绑定、被动、命座、静态规则和能力状态；校验、内容编辑、培养、计算与导出消费同一份定义。

每个角色在一份JSON中维护自身属性、参数、缩放项、计算模板选择、条件、效果、被动、命座和覆盖声明。动作编排与时间轴定义可另存一份可选文件，通过稳定身份引用伤害输出。单次伤害计算所需的条件、捕获策略和效果时效保留在角色定义中，实际时刻、事件顺序与动作产生的状态变化由动作定义和项目事实提供。

动作状态算法由版本化TS执行，JSON配置受控转换、守卫和时效来源。独立层数逐层过期，资源不足拒绝，容量、消耗或动作时刻缺依据时保持未知。派生状态按对象、事件及before/after阶段读取；动作后的状态不能提前用于动作前。动作文件存在不表示能够自动生成完整轮转或证明全部操作可执行。

角色专属定义集中在所属角色，武器和套装的专属规则集中在所属装备。普通伤害、防御、抗性、暴击、反应、排序与概率算法由引擎的版本化TS模板维护。跨实体公共配置与数值表按职责集中，导出时装配实际可达的数据及模板版本引用。公共定义保持单一维护来源，生成的运行分块和导出快照分别按用途组织。

说明模板引用已声明参数，采用受控文本渲染。命中从相同参数集合读取等级值，命座加级使用结构化声明。轻量列表和运行分块按需投影；完整数据配置与所需模板版本保留在配装快照中；离线复算仍要求运行时支持对应算法版本，文件不携带可执行实现。

武器和套装也使用各自共同契约。实体与参数标识唯一，引用须存在；规则声明单位、来源、解锁条件和支持状态。无独立伤害的技能显式表达其性质，辅助效果单独声明能力。

## 数值与规则

比例保存为小数，等级保存为整数，时间保存为整数毫秒。源参数保留原精度，单位在明确边界转换一次。运算使用双精度，显示舍入在展示层完成。来源精度、显示精度和运算精度分别核对。

JSON只选择已注册模板并提供参数、条件、效果和绑定，拒绝运算节点、脚本、输入签名或乘区算法覆盖。新增模板或改变通用算法须修改TS并明确版本；既有模板内修改倍率、缩放项及合法条件仍只改所属实体JSON。依赖图和运算追踪属于引擎内部实现。[命中输入](calculation.md#命中输入与附加缩放)、[属性捕获](calculation.md#命中属性捕获)和[基础加值](calculation.md#附加基础伤害与适用事实)各自声明所需事实。计算支持按查询依赖判定，未知值保持未知。

## 维护流程

内容作者维护正式输入；生成器校验并构建派生物，只读检查直接比较来源数值与生成结果。采集、候选制备、审阅采用分别执行，普通生成离线运行。

既有配装继续使用自身快照。采用新内容通过显式审阅更新计算副本；内置派生为自定义时保留派生关系，并重新确定核验身份。

具体来源、精度审计与采用记录见[内容资料](../tools/data/README.md)，维护入口见[内容包](../src/game-data/README.md)。
