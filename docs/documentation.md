# 文档规范

文档说明长期有效的目标、职责、设计理由、规则和工作流程。按主题组织内容，每项约定有一个维护位置，其余文档引用该位置。

## 内容归属

| 信息 | 维护位置 |
| --- | --- |
| 产品思路、通用契约、开发与设计规范 | 文档 |
| 实体定义、参数、映射与资源身份 | 内容与资源的正式输入 |
| 日期、固定版本、具体对象、来源与案例 | 工具资料及来源、审计记录 |
| 字段清单、实现导航、具体命令 | 所属目录的 README |
| 私有原件 | 获授权的本地忽略目录 |
| 截图、运行报告、测量与构建记录 | 输出目录 |
| 讨论经过、方案演变与迁移过程 | 版本历史 |

通用公式、单位、精度、字号和控件尺度属于规范。具体实体的数值、支持清单和逐项对照由正式数据及调查资料维护。

## 写作与更新

直接写明采用的设计、成立条件、行为和理由。规则用肯定句表达；状态用明确字段或简短表格表达。标题围绕概念与职责，正文采用简短段落和必要的表格。

整理时先提取有效结论，核对原文来源、最终决定、适用条件和去向，再合并重复说明。保留关键取舍及开发讨论形成的结论，具体材料随其用途归位。

每个模块或工具资料目录以一份 README 集中维护实现说明、操作、来源和已确认约定，使用章节及页内链接组织细节。

文档采用 Markdown、UTF-8、LF 和一个末尾换行。维护完成后检查内容归属、结论覆盖、链接、命令及生成器引用。
