# 事件时间与结算约定

> 适用范围：本文说明当前自动模拟实现。未来的视频打轴与配装优化工作台仍在规划，见[产品方向](../planning/product-direction.md)。

引擎采用整数毫秒，不对输入小数静默取整。小于毫秒的游戏机制精度若确有需求，需要调整规则版本和时间表示。

调度键为 `(timeMs, priority, insertionSequence)`，数值越小越先运行。动作序列采用到期事件 -2、增益开始 -1、命中 0，使增益在 [开始, 到期) 生效。同类事件按输入顺序处理。同一回调中新插入的事件参与后续排序，不能回到已执行事件之前；禁止向当前时间之前插入事件。

`runUntil` 包含截止时刻，可以分段推进；未到期事件留在队列中。单次默认处理预算为 100000，超限时保留待处理事件并抛错；回调抛错时已取出的事件不回滚。业务层应将异常视为该次模拟失败。禁止嵌套运行同一个调度器。每次模拟创建独立实例。

调度器已接入网页的独立人工测试动作序列。输入最多10000个命中、1000个增益，模拟时长最多1小时。增益 ID 必须唯一，不同 ID 的伤害加成相加，暂不支持刷新、同类覆盖或叠层上限。所有命中动态读取当时增益，不实现快照。增益可晚于模拟终点到期，终点后的到期事件不输出。结果包含总伤害、以完整配置窗口计算的 DPS 和所有窗口内事件。

单次攻击与动作序列是独立验证场景，尚未共享配队或属性编辑。后续加入真实角色前必须补充技能、冷却、命中时机和增益来源模型。

琴技能配置另有施放命令事件，优先级为1，晚于同刻增益和命中。施放时判定动作锁及冷却，命中时读取增益；动作锁与冷却采用截止时间比较，在边界时刻允许新动作。尚不支持取消动作、切人或多角色。

以上数值为保留的旧验证入口。阶段3统一战斗入口使用更完整的优先级：到期-30、增益/减益开始-20、回能到达-10、命中0、施放/切人指令10。该入口支持切人与多面板，详细语义见 `../mechanics/combat-v1.md`，不要混用两套入口的事件优先级常量。
