# 导入资料与计算条件的边界

2026-11-10。针对菲林斯展柜生命值导入问题复查当前链路，落实用户确认：当前生命不是培养资料，展柜导入无需判断或补填生命比例。

## 数据分工

| 内容 | 所属位置 | 使用方式 |
| --- | --- | --- |
| 角色介绍、技能文本、成长与倍率、静态规则 | CharacterDefinition | 内置、自定义、展示和计算共用契约；文本齐全不等于机制已核验 |
| 等级、突破、命座、基础天赋等级、武器培养 | Build | 表示所选培养与配装，不携带当前生命或战斗状态 |
| 圣遗物词条与身份 | 账号实物库存／独立展柜装备快照 | 展柜与实物在用户确认后按内容匹配；公开响应不证明实物身份 |
| 生命门槛、暴击、反应 | damage.conditions／damage | 由命中条件显式提供；缺失保持未知，不从角色展柜推断 |
| 等级、抗性、减防、无视防御 | 项目 enemy | 保留既有目标界面交互；表单初始值只是计算假设 |
| 面板与伤害结果 | 引擎求值结果 | 结果保留 invalid／partial／complete 及诊断；不据此擅自在角色面板追加文案 |

## 本次发现及修正

1. 生命数据校验曾导致整位展柜角色无法导入。移除导入器和交换契约对 fightPropMap 的要求，不读取当前生命、生命上限或其它战斗面板字段。
2. 生命比例曾混入通用配装，编辑、导入可能覆盖计算条件。Build 移除 hpRatio；角色培养页撤掉生命输入。具体命中使用 damage.conditions.hpRatio；本次不自行添加界面输入项。
3. 添加队员不再自动创建90级、10%全抗性目标。目标界面保持原有已确认交互，本次不自行追加确认按钮或新流程。
4. 内部批量添加命中函数曾默认不暴击、无反应。现在默认均为未确认；显式计算用例必须自行提供选择。
5. 复制到项目的角色、武器和伤害定义曾共用 verified:true。现在分别检查角色来源、当前命座支持、武器与适用套装规则；不把复制动作当作核验，也不把静态规则支持当作战斗观察。
6. 引擎保留机制支持与未知条件的结果状态；角色面板维持重构前表现，不自行追加诊断小字。
7. 属性面板缓存原先只按角色索引。现在同时区分命中条件，避免同角色不同生命条件的命中复用错误状态。

## 复查后保留的规则

- Mona equippedBy 继续只作穿戴备注，导入不设置本地穿戴、不创建独立组合。
- 展柜确认前不写入；快照与本地实物分开。“同时导入本地库”确认后覆盖所选角色的本地部位引用；快照模式和详情单件入库不改穿戴。物品允许多角色／配置／组合共享引用，不转移其他引用，不删除旧物品；内容匹配不证明游戏实例身份。
- 强化次数的推断候选、用户选择与已核验响应记录保持区别；默认折算基准有说明，不描述为玩家观察。
- 手动创建角色的满级初始值保留，用户可修改并显式保存；外部导入的培养字段不以这套默认值补齐。
- 五星圣遗物限制属于当前导入范围；未核验的角色机制属于计算支持范围，不据此拒绝合法的培养资料。
- 未选择目标、暴击、反应或必要生命条件时，不给出完整伤害结果；动作记录与资料展示仍可使用。

## 验证范围

菲林斯问题通过实际公开响应复现；按用户要求不保留专用fixture及其依赖用例。整个固定输入目录已删除；检查直接读取.references中的已有获授权原件，缺失时明确跳过。黎明神剑与C0对照属于基于真实资料的显式计算配置，不作为玩家原配装或游戏伤害观察。

定点检查包含培养与装备导入、忽略战斗字段、生命门槛独立求值、同角色不同命中条件隔离、账号与轴状态隔离，以及既有角色排序。没有重新执行全部浏览器、桌面与全阶段验收。

当前严格契约移除了配装 hpRatio；不提供旧文件转换，不主动操作已有用户文件或浏览器记录。长期规则见[文件与状态边界](../standards/files-and-state.md)。

## 有效条数与本轮UI清理

固定属性按白值折算的公式、具体角色/武器与默认基准的调用、组合冻结、去重、自动命名和对比规则均沿用现有实现。组合编辑只删除额外武器文案，平均条数只删除额外白值悬停说明，不删除计算所需基准或改变分母。

角色卡恢复原有天赋等级与命座加级显示，不追加“+?”或诊断悬停文本。培养页恢复原命座控件规则，不根据元数据完整性另加禁用或占位分支。元数据编辑功能保留，去除额外说明和来源/版本折叠；角色详情不恢复介绍区、生命输入或新增小字。
