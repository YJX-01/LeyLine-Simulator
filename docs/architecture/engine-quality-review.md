## 模块职责

| 模块 | 职责 |
| --- | --- |
| `team.ts` | 校验队伍、解析配装、编译角色动作和通用战斗输入、组装结果与范围说明 |

编译入口不再包含角色运行时实现。装备的生命条件加成、充能转攻击和绝缘增伤统一归装备模块，角色模块只处理角色能力。角色表使用 `CharacterKey`，遗漏角色条目时由 TypeScript 报错。

## 已修复的问题

1. **敌人减益过期回调误删刷新实例。** 静态配置的减益到期时原先直接按 ID 删除；若内容钩子以相同 ID 刷新，旧回调会提前终止新减益并记下错误的结束日志。现在与动态减益和召唤物一样，先检查当前实例身份。回归场景覆盖初始增伤、旧到期后的刷新增伤、真正到期后的基础伤害，以及仅在真正到期时记录结束事件。
2. **逐命令准备缓存保留到模拟结束。** 先前按命令 ID 的 Map 持有每个准备结果，包括拒绝的动作。改用按当前准备技能对象索引的 WeakMap，保留准备/施放的直接关联，允许无后续引用的准备数据回收，去掉未使用的 snapshot 字段。
3. **内部召唤物类型重复。** 通用结算直接复用 `combat-runtime.ts` 的命中、召唤物定义与实例类型，避免钩子和调度器后续各自扩展出不同字段。

## 生命周期与钩子约定

- `prepareSkill` 在站场、动作锁、冷却和能量校验之前执行。只能准备技能克隆和临时派生数据，不能提前消耗资源、随机数或修改游戏状态。
- `onCast` 在资源与冷却提交之后执行；返回 true 接管默认效果。普攻动作触发的协同攻击仍由通用运行时处理。
- 每次命中给 `prepareHit` 提供浅复制，避免命座/装备修正累积到后续同一召唤物的命中定义。
- 周期效果与召唤物刷新必须验证实例或 generation，不能只按 ID 取消旧任务。血梅香和雨帘剑维持已有刷新节拍；召唤物替换使旧回调失效。
- 所有可变状态均由模拟调用内部工厂创建，不存到模块全局。现有重复模拟隔离测试继续覆盖这一点。

## 后续结构约束

角色运行时仍包含五名角色的分支，尤其 `onCast` 是下一次扩展角色时的主要复杂度来源。新增角色前宜按独立角色能力模块注册钩子，保留统一资源、调度和命中管线；此次未引入公共插件接口或更改规则合同。天赋数组仍由旧数据快照的位置索引读取；本次集中读取入口，没有改变快照格式或补造数据语义。

此次未发现需要修改 schema 的阻断问题。固定单目标、无敌方攻击、无击杀事件与不支持草反应仍是既定模拟范围，保留结果警告。
