# 阶段5验收：配置、运行与方案分析

验收日期：2026-11-05。开发分支 `dev/typescript-rewrite`，仅本地提交，未 push、未部署。规则继续采用阶段4审计的数据快照和单目标范围，不将界面完成等同当前游戏全部机制验证。

## 使用流程

默认 `/` 与 `/#workbench` 进入玩家工作区。首先编辑队伍与配装，在动作循环页调整目标、种子、日志模式和时间表，再运行模拟。结果页提供伤害贡献、累计伤害、能量曲线、前台/增益时间线、反应统计及可筛选的逐事件结算。

可将有效运行固定为 A、B，比较总伤害、DPS、角色伤害与最终能量；差异明细同时列出队伍、循环、敌人、种子、模式及版本变化。差值方向为 B − A，零基准不计算百分比；不同窗口时长同时展示，避免只看总伤害。

方案管理提供保存、载入、复制、重命名、删除及 JSON 导入导出。JSON采用已存在的 `TeamInput` v1合同，不执行旧Python文本指令，也不猜测未知版本。结果导出包含本次实际提交的配置与版本，独立于当前编辑状态。原验证入口 `/#tools`、`/#team`、`/#combat` 保留。

## 实现边界

| 层 | 责任 |
| --- | --- |
| `Workbench.vue` | 组织工作区导航和编辑/运行/方案流程 |
| `components/TeamEditor.vue`、`LoadoutEditor.vue` | 角色槽位、兼容武器、天赋、圣遗物和属性来源预览 |
| `components/RotationEditor.vue` | 动作分页编辑、复制/删除、稳定排序与同刻手工调整顺序 |
| `stores/workspace.ts`、`plans.ts`、`comparison.ts` | 草稿、持久化方案和两份独立运行快照 |
| `domain/team-task.ts`、`composables/useTeamSimulation.ts` | Worker所有权、任务代际、错误、取消及运行前内容校验 |
| `domain/results.ts`、`comparison.ts` | 可单测的曲线/时间线模型和配置差异/数值对比 |
| `components/ResultPanel.vue`、`ResultChart.vue` | 结果解释、分页日志及ECharts生命周期 |

引擎不依赖Vue、Pinia或ECharts。编辑器草稿与Zod解析缓存使用独立副本；已提交配置、已返回结果和对比快照不随编辑变化。结果数组使用浅引用，最多固定两份对比快照，避免整个事件树深度响应化。

## 已验收行为

- 1—4人队伍，同一角色不重复；增删槽位时修复前台引用，移除对应动作。替换角色保留槽位引用并重置为兼容配装，不静默删除其他动作。
- 等级/突破、天赋、命座、生命/能量、8把武器及5个圣遗物部位编辑；百分数输入转换为引擎小数。即时面板复用 `resolveLoadout`，运行前继续检查装备、天赋、能量与角色动作条件。
- 动作表每页25条，最多2000条，毫秒精度；同刻指令保持原顺序，显式稳定排序。长按仅用于琴E；阿贝多Q要求明确生灭之花命中数。
- 取消、编辑或新任务使旧代际消息失效，Worker异常和消息读取错误释放实例，允许重跑。配置修改后保留旧结果但明确标记，禁止将过期结果固定为当前方案对比。
- 累计伤害末值与引擎总伤害对账，各角色能量末值与最终能量一致，前台区间覆盖完整模拟窗口。增益替换、刷新和截止时仍生效的区间正确闭合。
- 日志每页40条、状态时间线每页30段，筛选/新结果重置页码。摘要模式仅显示总量，明确不提供未记录的事件曲线。
- 草稿有效配置300ms延迟写入，本地方案库最多50条、UTF-8 JSON最多1MB。无效编辑不覆盖最后有效草稿；损坏/未知版本存储保留原值并提示，配额失败不更新内存方案列表。
- 方案CRUD、导出后导入、未来版本拒绝后恢复、两次运行对比、取消与Worker加载失败恢复均通过浏览器用例。
- 390px视口下表单和摘要结果没有页面级横向溢出；宽表在局部滚动容器内。桌面/窄屏截图已人工检查，截图由测试生成于忽略的 `test-results/`。
