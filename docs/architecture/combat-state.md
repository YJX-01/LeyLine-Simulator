# 战斗状态标注与读取

当前覆盖候选队员的生命比例、站场及护盾存在状态。敌方状态、受击／有效治疗事件和自动触发没有因此实现。

## 当前契约

项目可选字段combatStates保存区间：id、actor、startMs、endMs和values。actor引用candidate.actors中的队员，values可提供hpRatio、onField和shielded；生命比例为0至1，另外两项为布尔值，各字段均允许null表示明确未知。每个区间至少标注一个字段。

区间为整数毫秒的左闭右开区间[startMs,endMs)，必须非空。同一队员同一字段的区间不能重叠，即使数值相同也拒绝；不同字段可分别标注。相邻区间允许共用端点，不由数组顺序裁决。标注不会随命中、治疗或护盾量自动改变。

damage.conditions继续表示命中所属队员的字段覆盖；damage.stateOverrides允许按actor覆盖本次命中上下文中其它队员的字段。同一命中对同一队员同一字段只能覆盖一次，不允许两个入口重复填写。引用不存在的队员直接拒绝，动作记录不能携带damage或命中覆盖。

读取某队员某字段时，先取本次命中的显式覆盖，否则取该时刻该队员的区间，否则未知。未提供字段继承区间；null不回退；零生命、false和未知分别处理。所有队员合并区间与覆盖后不能同时有多位明确站场；一位站场不自动把其它队员推断为后台。

## 求值与来源

每次求值重建区间索引和缓存。角色属性读取使用所读角色的状态，不能把当前命中的生命比例传给队友。伤害面板使用同一套解析后的状态，保证属性依赖与最终暴击等乘区一致。

命中覆盖仅属于该命中上下文。读取来源动作或捕获记录时使用那条记录的时刻和上下文，不携带后来命中的覆盖。状态区间独立于事件的before/after阶段；同毫秒的两阶段读取相同区间，事件触发的效果仍按现有timeMs/order/id和前后阶段处理。当前不把区间端点伪装成额外动作或触发事件。

独立evaluateDamage没有项目队员引用上下文，收到非空stateOverrides时明确拒绝，不静默忽略；时间轴先解析对象覆盖，再将当前队员的conditions传入独立伤害公式。

EvaluationResult.stateReads记录实际查询过的队员、字段、时刻、记录ID、值及来源类型。intervalId保留所在区间，即使命中覆盖取代了其值；source为override时以覆盖为准。source=unknown表示没有标注来源；interval或override的value=null表示该来源明确未知。结果不回写项目、账号或Build。

当前生命比例已被黎明神剑等既有静态条件读取；onField和shielded已具备记录、校验和解析能力，尚不因此新增角色或装备触发支持。治疗或护盾计算量不会变成实际生命变化或护盾存续事实。

## 文件与编辑

新增字段均为可选的加法扩展，现有字段含义保持，项目封装仍为2、规则仍为timeline-v1；没有引入另一套旧格式、迁移或回退读取。保存/打开、恢复和Worker通过共同projectSchema保留标注，旧版本标签仍按现行规则拒绝。

web/domain/combat-state提供区间设置／删除和命中覆盖设置／清除操作，校验失败保持草稿。删除队员同时移除其区间及其它命中对该队员的覆盖。计算器已有单次状态输入，时间轴尚无完整区间编辑入口。

当前能力边界见[支持范围](content-support.md)，文件语义见[文件规范](../standards/files-and-state.md)。
