# 开发与交付

## 工具维护流程

维护工具按采集、候选制备、正式生成、只读检查、构建、交付和清理分工。每项命令有唯一正式入口，依赖在其所属包声明。

来源更新是显式动作，保留原始字节、版本、单位和身份；候选写入新的审阅目录，核对差异后采用正式输入。普通生成离线读取正式内容，确定性构建派生物并复用相同字节。

只读检查比较来源、正式内容和派生结果，失败返回非零并指出字段或文件。文档按[文档规范](documentation.md)维护，逐项数据对照由正式输入与生成索引提供。

工具从仓库根定位路径，平台运行代码归应用，功能检查归测试。共享工具函数由实际复用关系组织。

清理先预览并核对解析后的绝对路径、目录链接和跟踪状态，再处理约定输出。用户资料、原件、待审候选及保留的交付包各自维护生命周期。

具体环境、命令、输入输出与写入范围见[工具命令](../tools/README.md#工具命令)，交付步骤见[交付操作](../tools/README.md#构建托管与本地交付操作)。

## 构建与交付

网页和桌面复用同一应用与正式内容。构建先离线生成并校验输入，最终包独立于开发缓存运行，许可、图片和索引随包分发。

### 验证与版本

日常检查按改动选择，交付以冻结源码和匹配的验证证据为准。开发网页、桌面、根路径及子路径分别核对；浏览器与桌面串行、单工作线程执行。

报告保留源码指纹、实际检查范围、平台和结果。候选准备要求当前完整浏览器矩阵成功、报告与源码及用例清单匹配。功能检查和游戏观测按[证据规范](evidence-and-validation.md#来源独立核验与观测)分别登记。

桌面与网页交付各保留最新和上一次成功包。新包在独立临时工作区完成并验证后原子更新入口，再淘汰更早版本；失败清理当前中转，原有成功包保持。运行中的桌面包留待关闭后清理。

### 托管与分发

页面通过安全网页协议或本地主机提供，后台任务及分块从同源正确类型的资源加载。入口使用重新验证缓存策略，带内容摘要的静态资源使用长期不可变缓存，失败响应使用即时失效策略。

部署采用完整版本或原子切换，先资源后入口，回滚恢复整版。子路径与构建基址一致，旧页面所需资源保留过渡期。存储按站点来源隔离，更换地址前导出资料。

第三方许可原件集中维护，构建分发副本与原件一致，设置页提供许可及鸣谢。候选生成、验证和外部发布分别执行。

具体命令、路径、缓存配置和分发字段见[交付操作](../tools/README.md#构建托管与本地交付操作)，测量方法见[性能检查](evidence-and-validation.md#性能测量)。
