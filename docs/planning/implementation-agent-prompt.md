## 4. 三个连续可运行增量

### P3-A：通用效果与来源修订

实现显式同组覆盖/叠层、跨角色属性转换及用户定义效果，展示可用效果候选和实际采用来源。支持禁用/修订来源实例，换装后重新生成规则及检查修订有效性。有限数据通过受控操作表达，不执行任意 JS，不写角色名称特判。

同刻排序沿用新轴的确定性 `(timeMs, order, id)`，捕获前后等新阶段显式定义；不能直接搬旧模拟器的 priority 常量。补覆盖/叠层上限、区间端点、同刻动作先后、跨角色循环、未知条件与修订失效的独立测试。

### P3-B：属性级捕获与动态读取

实现效果自身捕获、技能属性捕获与动态乘区混用；每次候选变化重新计算，不能缓存上一配装的最终面板。读取可追到角色、源实例、时刻、阶段、属性及对应依赖。

独立期望：辅助在1秒攻击1500，捕获20%得到300；输出在3秒捕获攻击2300，7秒动态增伤50%，伤害 **6900**。辅助基础攻击改1200后为 **7020**；把 Buff 改为动态读取后为 **6600**。保留原手算依据，不能由待测引擎生成期望。

### P3-C：计数、累计、结算和重置

将前序伤害、计数、累计与效果放入同一依赖求值模型。不能“先算完所有 Buff 再算伤害”而断开依赖此前伤害的效果。仅选结算点为目标时仍保留其前序依赖。

独立期望：1秒100、4秒200、6秒普通命中900；6秒结算读取 `[1000,6000)`，合计300，乘0.5得 **150**。前两次改120/240后为 **180**；6秒普通命中被右端点排除，结算不含自身。构造真正包含当前结算的自引用须报循环。另补计数初值/上限、结算后重置、连续窗口、同刻先后、未知依赖与预算测试。

三个增量都需要可保存输入和真实 UI 消费者。原 future-samples 是非生产参考，不可直接改 `productionSupported` 为真；新增生产契约 fixture，接入引擎与 UI 后才更新状态。合成内容用于证明通用机制；至少将 P3 属性/效果读取接入既有真实配装路径，保留三角色独立数值，并用独立输入验证真实角色收到跨角色效果后重求值，避免真实数据永久留在独立静态分支。无需因此扩充全部真实角色/命座/技能。
