P0/P1 已提供纯计算内核、独立样本和 CLI，保留其结果。当前先完成 D0，把已支持能力做成桌面可操作闭环，再补齐 P2 的完整编辑/撤销/Worker 等能力，随后进入 P3 的跨角色效果、快照与累计。P0/P1 的“无界面”描述是历史内核里程碑，不能继续作为用户验收的最终交付形态。

不恢复旧自动模拟器的角色重构，不将旧模拟器页面包装后称为新工作台验收。原有功能可以保留独立入口，默认入口应明确展示新工作台。

## D0 的 UI 范围

用户不使用命令、不手改 JSON，便可完成以下流程：

1. 打开桌面应用，加载合成普通伤害样本。
2. 在输入控件中调整攻击、倍率、候选武器、效果加成与区间、伤害记录时间、条件真/假/未知及目标伤害点。
3. 查看逐点伤害、全轴总伤害与目标值，展开公式/来源及诊断；未知值明确显示“待确认”，不伪装为零。
4. 保存项目并重新打开，得到相同定义、候选、轴和求值结果；导入失败保留当前项目。
5. 通过 UI 进行 P0/P1 独立参考验收，明确区分预期值和实际结果。

普通伤害验收依次覆盖 A 为 4400、B 为 4000、A 攻击 1100 为 4840、只选第二次命中为 2000。界面还应让用户看见换武器时效果消失、区间端点、条件未知与 false 的差异。快照 6900/7020/6600 和窗口累计 150/180 仍是后续样本，显示未支持状态，不生成假结果。

受控表达式完整可视编辑、自定义跨角色效果、视频打轴、优化搜索、账号导入、自动更新、签名安装包等不因 D0 提前实现。若本轮仅交付样本字段编辑，不能称为完整 P2 自定义公式编辑器。项目高级输入可以保留导入/导出能力，但默认验收流程不依赖原始 JSON。

## 平台边界

账号与轴项目独立：用户已要求角色、圣遗物分别设栏，并可保存账号信息；项目就是一条轴。共用 UI 和存储应分别标识账号资料与项目快照，账号更新不自动覆盖旧轴，轴内候选变化不自动覆盖实际装备。具体侧栏分组和账号字段见[导航讨论](ui-navigation-discussion.md)，此处记录方向，不表示账号存储已实现。

角色栏可直接调整并保存本地账号的实际装备，用户已确认允许。账号实际配置与轴内候选方案使用明确的保存对象与状态提示；不隐式同步，也不声称支持游戏端回写。

桌面采用独立应用窗口并加载本机构建产物；正常运行不要求先启动浏览器或 Vite。开发命令只用于开发者，不代替面向用户的可双击入口。交付应给出实际可打开的位置，并说明是否为开发/未签名版本；不能将下载依赖或构建命令冒充用户启动方式。

默认启用上下文隔离、关闭 renderer 的 Node 集成；只经最小受控桥接暴露所需能力。桌面文件操作使用用户明确选择的文件，不向界面暴露任意脚本执行或通用文件系统接口。网页用相应文件选择/下载适配，共用项目序列化和校验，不复制计算逻辑。

CLI `tools/scripts/evaluate-workbench.mjs` 继续作为 agent 入口，读取与 UI 导出的同一 v1 项目。UI 和 CLI 对同一输入应得到一致结果；后续编辑命令也应在 domain 层形成可复用操作，而非只存在于组件事件中。

## 并行与检查

- A 持有桌面壳、共享配置、依赖清单、打包和集成；共享计算契约有变更时统一处理。
- B 持有共用 Vue 工作台与平台适配调用，不另写一套数学公式。
- C 更新计划与使用说明，记录交付范围和能力限制。
- D 独立验收普通算例、未知诊断、保存重开及桌面/网页/CLI 一致性。

文件所有权先确定，不同时修改共享导出、根配置或锁文件。浏览器测试覆盖实际 UI 操作，桌面测试验证原生窗口打开并操作同一界面、离线本地资源及保存重开。运行原有数据、fixture、架构、类型、单元测试、构建及预算检查；新增桌面依赖必须声明于所属清单并与锁文件一起保存。实际验证结果及未解决项写入交付记录，未运行的桌面检查不能标成通过。
