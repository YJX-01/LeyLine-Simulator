# 模块边界与扩展原则

状态：用户已认可的设计原则；具体实现与支持范围以[整合记录](desktop-integration.md)及[实施路线](implementation-roadmap.md)为准。本文不另行维护阶段任务。

第一轮具体方案及验证算例见[总体设计草案](overall-design.md)，其中未定技术细节不视为已确认需求。

代码落点与实现提案见[核心代码方案](core-implementation.md)，分阶段搭建与验收见[实施路线](implementation-roadmap.md)。

## 主线与模块职责

### 产品层的三个独立模块（用户已认可）

| 模块 | 保存对象与职责 | 与其他模块的关系 |
| --- | --- | --- |
| 账号资料 | 长期保存的具体角色、武器、圣遗物库存与实际装备 | 为多条轴提供可选资料，实际装备可在角色栏编辑保存 |
| 轴项目 | 一条轴及其队伍、候选配装、标注、条件、目标和计算分析 | 主要工作区；队伍、时间轴、分析和优化是同一项目的不同视角 |
| 内容定义库 | 角色、技能、武器、效果、伤害公式的规则定义，内置与自定义共用 | 与账号、轴并列，可供多个账号资料和轴项目复用，允许虚构角色 |

账号中的角色是用户持有的具体实例，定义库中的角色是计算规则；二者不混为同一对象。轴从账号资料及定义库取得所需数据后，保留实际使用的版本和快照。账号更新、实际装备编辑、定义更新均不自动覆盖已有轴；主动更新或升级是显式操作。轴内候选配装不自动回写账号。

以上为产品模块划分，不要求新增 workspace 或建立三个独立应用。桌面、网页及 agent 接口使用相同契约和业务能力，平台差异由适配层处理。

实际装备按实例唯一占用；从另一角色转移装备必须明确提示并由用户确认。账号实际装备保存与轴候选保存分别操作，导入、切页和候选求值不得隐式同步二者。

### 共用界面与中文展示

持续侧栏按三个产品模块分组，角色和圣遗物独立入口；顶部明确当前账号、当前轴和保存对象。切页保留编辑及选中状态，时间轴与分析共用目标集合和计算结果，分析可定位到记录。窄窗口使用折叠菜单与自适应检查面板，桌面与网页不维护两套业务界面。

内置用户可见文案使用中文。展示层将属性、条件、诊断与规则的机器标识映射为中文名称；展开的技术详情可保留原始标识和来源路径，用户自定义名称、品牌及必要单位例外。机器 ID、序列化字段和版本不得翻译。文案集中且可替换，为远期语言字典留边界，当前不引入完整国际化框架。

### 计算与编辑职责

围绕“记录 → 推导 → 计算 → 优化”划分模块，通过明确的数据契约连接。角色内容提供规则，不决定整个系统的架构。

| 模块 | 职责 | 扩展方式 |
| --- | --- | --- |
| 数据接入 | 读取角色、圣遗物，转换为内部格式 | 为不同公共接口添加适配器 |
| 时间轴记录 | 保存动作、伤害点、充能等标注 | 添加新的记录类型 |
| 规则推导 | 根据记录与条件生成 Buff 等效果 | 注册角色、武器、套装规则 |
| 属性计算 | 根据配装和效果得到计算所需属性 | 添加属性与转换规则 |
| 公式构建与求值 | 将伤害点编译为可重复计算的表达式 | 添加伤害计算规则 |
| 优化 | 改变允许的变量，比较结果 | 添加搜索算法、目标与约束 |
| 编辑交互 | 视频播放、快捷键、时间轴编辑 | 添加操作方式和展示组件 |

以上是逻辑边界，不要求每个模块立即独立成为一个 workspace。

## 数据接入与项目快照

角色导入对接其他项目提供的接口；圣遗物兼容莫娜占卜铺格式，优化算法以其上游项目 [wormtql/genshin_artifact](https://github.com/wormtql/genshin_artifact) 为复用来源。具体接口、格式版本与算法接入方式待源码核对。

外部格式通过适配器进入内部模型，不直接成为所有模块共同依赖的数据结构。算法复用与项目自己的目标函数、效果求值及候选约束衔接，适用性待验证。

导入数据保留项目快照，用户主动更新时才改变已有项目的数据依据。项目支持本地保存与文件导入导出，不依赖账号、云端或公共接口持续在线才能打开和计算。

项目同时保留计算规则与游戏数据版本：旧项目沿用原版本，主动升级时展示相关规则、Buff 和伤害变化；新项目默认采用最新版本。版本保存与旧版求值策略待设计，需确保对应的计算行为可恢复，而不只是记录版本标识。

## 记录与交互解耦

快捷键最终产生“添加动作”“添加伤害点”等编辑命令。鼠标操作、批量导入及后续录入方式调用同一套编辑能力。

撤销、重做、校验和保存以编辑命令及记录模型为基础。修改快捷键不改变记录格式。

轴模型独立于视频资源。视频只是可选标注参考，缺少视频时仍可编辑、计算、优化和分享轴。

## 原始记录、推导结果与计算结果分离

例如，用户记录某角色在某时刻施放爆发，规则据此生成 Buff，伤害点读取对应效果并构建公式。

三类数据保留明确的来源引用。修改动作后可以重新推导相关效果；人工观测和人工修订独立保存，不能因自动更新而丢失或混淆来源。

## 内容规则共用效果能力

内置与自定义内容共用一套定义能力及计算路径。内置角色、武器、套装与敌人是已验证预设，允许从预设复制修改或自行创建；来源、版本和验证状态区分。新增内容优先增加定义，模型无法表达的新机制才扩展公共层。

公共层提供持续时间、叠层、覆盖、作用对象、属性修改和快照引用等能力。角色、武器和套装模块分别定义触发条件及产生的效果。

适合数据表达的规则使用数据；复杂规则允许使用受限的类型化函数。开发初期不先建设完整的技能脚本语言或动态插件加载系统，优先采用显式注册。

已确认 Buff 推导按可用信息处理：动作和配置足以确定的效果自动生成；依赖额外条件的效果读取标注或由人工补充；尚未支持的特殊效果允许手工添加并注明来源。

自动 Buff 支持查看、禁用与修订，人工修订单独保存。缺少触发条件时保留“待确认”状态，不隐式转换为生效或不生效，支持集中处理。已明确的部分可继续编辑和分析；正式优化前集中确认影响目标函数的未确定条件。

Buff 添加界面优先使用当前队伍及配装生成候选列表，不以全部 Buff 池作为默认选择范围；候选筛选与实际生效判定分离。

自定义 Buff 支持固定增益、队伍角色属性引用及受控运算，属性转换随候选配置重新求值。引用关系进入公式依赖模型，具体运算能力、循环依赖处理和编辑形式待设计。

## 独立的计算表达式模型

整体伤害公式内部采用结构化表达式，文本公式作为展示形式。具体结构与序列化格式待设计。

表达式明确区分：

- 可替换变量，例如圣遗物属性。
- 来自时间轴的固定事实，例如伤害点及其归属。
- 需要重新判断的条件，例如属性阈值和 Buff 生效条件。
- 数据与规则版本。

优化器通过允许的变量赋值并求值，不依赖视频、快捷键或角色运行回调。更换搜索算法不应要求修改打轴模块。

## 模板复用时重新推导效果

已确认同时支持实际轴分析与模板配装比较。模板保留整体动作及伤害点结构，允许更换武器、调整圣遗物词条等输入。

配置改变可能影响效果规则与 Buff。一次候选方案的计算流程应包含根据记录和候选配置重新推导相关效果，再构建或求值公式；不能只替换最终面板属性，也不能固定沿用原方案的 Buff。具体缓存、增量更新及表达式复用方式待设计。

方案对比需要保留效果差异及其与伤害点的关联，支持解释新增、消失或改变的 Buff 对结果的影响。

候选配置可能因攻速、充能等变化而不再满足原轴条件。相关适用性检查与自动动作推演分离：保留记录，提示用户核对，由用户决定是否修改。检查能力的具体范围待设计，不能将未检查解释为已验证可执行。

## 实际配装与理论分析共用计算能力

已确认同时支持库存内实际配装与自由配置理论分析。两者共用轴模板、效果推导及公式求值；候选配置的来源与约束分别处理。

实际配装需要保留装备实例身份，并防止同一队伍方案中的多个角色重复占用同一件圣遗物。理论分析允许设置不来自现有库存的武器和词条，具体合法性边界待设计。

优化器最大化一个最终目标函数，默认取整条轴的总伤害，并预留用户自定义目标函数的能力。目标函数求值与候选范围、约束及搜索算法解耦；不额外添加少换装备、充能更宽裕等隐含偏好。

自定义目标的表达形式、具体约束和搜索算法仍待确定。

已确认允许按角色、时间段、技能或指定伤害点筛选目标伤害，并最大化其合计。目标筛选与计算依赖范围分离：不因只优化某人的伤害就删除队友动作及 Buff；所选伤害仍在完整轴的相关上下文中求值。选择界面和其他自定义函数形式待设计。

目标统计范围与优化变量范围也分别定义。选择某个角色的伤害作为目标，不意味着只搜索该角色的配装；允许全队配装参与调整，并支持用户锁定角色或装备。变量范围仍受库存唯一占用与合法性等约束，具体锁定粒度待设计。

## 敌人条件的时间关联

敌人条件包含基础设置和时间分段变化，覆盖等级、抗性以及易伤、阶段变化等信息。伤害点按对应时刻读取条件，作为计算上下文的一部分。

按一条轴通常对应一个敌人设计，不以多目标作为常规需求。敌人及阶段定义由敌人元数据数据库提供，轴记录所选敌人及阶段时间区间。阶段规则与某次记录中的阶段发生时间分别保存。

具体字段、区间边界及重叠处理待设计。区分敌人阶段条件与队伍规则生成的效果来源，避免重复计算。

## 战斗状态标注

生命值、护盾等条件通过时间段标注进入计算上下文，伤害与 Buff 规则读取对应状态，不依赖完整的受伤、治疗过程推演。具体字段、角色归属及配装变化后的适用性待设计。

## 可选充能能力

元素球掉落记录及据此生成的充能约束属于可选辅助能力，不作为核心标注、伤害求值或优化的强制依赖。相关约束由用户选择启用，不改变单一目标函数最大化的原则。

未提供充能记录时允许继续计算和优化，但不能据此声称充能可行性已验证。记录字段、拾取与到达条件及约束生成细节待设计。

## 分析与可视化

支持基本的配置变化展示，重点通过可视化呈现伤害乘区与属性投入的效果，帮助用户识别收益下降、上限及无效投入。具体图表与交互待设计。

分析应从公式和效果求值结果获得依据，不在展示层另行实现伤害规则。明确区分硬上限、条件不适用和边际收益降低；后者不能直接视为无效或硬性溢出。相关指标的定义与计算方式仍待设计。

分析结果用于解释与比较，不改变单一目标函数最大化的优化原则。

已确认的分析视角包括角色/技能/时间段的伤害构成、配装变化对乘区及伤害点的影响，以及属性增量对最终目标函数的收益。属性收益默认围绕整条轴总伤害展开；图表形式、增量单位和计算口径尚待确定。

## 技能与 Buff 的快照

快照属于核心计算能力，技能与 Buff 均支持按规则使用快照或动态取值。不能将整个技能或效果的所有属性无差别地固定在同一时刻。

内置规则指定捕获的属性、捕获时刻及仍动态读取的部分。伤害点关联动作或效果来源，特殊情况允许人工指定快照来源；分析结果可追溯取值时刻。该能力与自动命中推演分离。

快照的计算关系保留在模型中，每个候选配装根据指定上下文重新求值，不复用原配装的固定数值。具体粒度、关联契约及人工编辑形式待设计。

## 概率与历史依赖

支持复盘与期望两种口径，共用轴并明确区分计算依据。复盘读取已标注的实际情况；期望按概率规则求值。复杂效果涉及条件、阈值和快照时，不将平均增益或平均次数代入视为普遍正确的期望算法。具体求值方式、支持范围及近似标识待设计。

规则模型支持事件计数、叠层、时间窗口累计，以及根据累计伤害按系数结算等能力。明确统计对象、归属、时间窗口、上限、结算与重置时机和取值方式，基于已有标注重新求值。

历史依赖进入计算依赖模型，候选配装改变后重新计算。明确同刻事件先后、累计边界并检查循环依赖，避免累计伤害自引用；不因此引入完整自动战斗推演。

## 自定义伤害与角色建模

自定义伤害公式属于核心扩展能力，可引用角色属性、Buff、计数器和累计值，并进入相同的分析及优化流程。支持虚构、未发布角色的建模，自定义内容保留来源与验证状态，不混同已验证内置规则。

公式采用受控表达式，不执行任意代码。具体语法与角色定义范围待设计，需共享属性引用、快照、概率、历史依赖及循环检查等计算契约，避免另建一套不兼容的计算路径。

## 条件完整性与优化前确认

项目保存、编辑和已确定部分的结果展示不要求所有条件已经补全。未确定项及部分结果的范围需明确标示，不静默代入默认假设。

正式优化前集中确认影响目标函数的条件，检查覆盖所选目标及其效果、属性等计算依赖。该检查不强制启用可选充能能力。具体依赖检查与确认交互待设计。

## 契约与独立算例

每个模块明确输入、输出和缺失数据的含义，尤其统一以下语义：

- 时间单位和持续区间。
- 属性单位及加算、乘算关系。
- 未填写条件与明确否定条件的区别。
- Buff 叠加顺序和属性转换依赖。
- 快照捕获的值及捕获时刻。

测试使用独立算例验证这些规则，不能只验证某个角色的最终总伤害。

## 后续设计顺序

先明确三个核心数据契约：标注项目、效果规则、计算表达式。关系稳定后，再评估现有公式、配装解析、Buff 等实现的复用。

P0/P1 与桌面主题切片已落地，后续按实施路线补齐 P2；未完成的机制仍逐项设计与验证。不恢复此前已回退的重构，也不按旧模拟器计划自动推进实现。
