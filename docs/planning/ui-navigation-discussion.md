## 账号与项目边界（用户已明确）

用户补充：角色与圣遗物应有独立栏目，拆开原“队伍与配装”；账号信息可以保存，账号与项目是两个对象，项目就是一条轴。导航据此分为账号资料和轴项目两个功能组，不再把资源仓库作为项目管理的未来附属项。

用户进一步确认：允许在角色栏直接调整并保存账号的实际装备。此处“实际装备”指本地账号档案中的配置，不表示已支持修改游戏内装备或向账号接口回写。轴内换装仍属于该项目的候选方案；二者独立保存，不自动互相覆盖。

账号保存长期使用的角色/装备资料；项目保存某条轴、使用的队伍与候选配置、定义及规则版本快照。一个账号可供多条轴取材，项目不依赖该账号持续在线或当前选中。账号切换、更新与项目切换是不同操作；更新账号不自动改写已有项目，项目内比较配装也不自动改写账号实际装备。

本轮确认“账号信息可保存”，不等于已经确定账号接口、联网登录、云同步、UID 必填、多账号数量或跨账号混配规则。先采用本地保存的资料档案作为实施提案，具体字段和使用方式继续讨论。

## 修订后的信息架构（具体排列待讨论）

| 一级功能 | 主内容 | 当前及后续边界 |
| --- | --- | --- |
| 账号 | 账号资料档案的创建、选择、保存及数据来源 | 与轴项目分别保存；具体字段、接口与多账号能力待讨论 |
| 角色 | 当前账号角色、属性、武器与实际装备查看、调整和保存 | 用户已允许编辑实际装备；与圣遗物库存分栏，和项目候选装备分别保存 |
| 圣遗物 | 当前账号库存、筛选、导入和装备实例 | 后续接莫娜格式；独立实物身份，不因属性相同合并 |
| 项目 / 轴 | 新建、打开、保存轴、项目版本、示例项目 | 项目就是一条轴；持有自身数据快照，不是账号容器 |
| 队伍 | 当前轴使用的角色和候选配装方案 | 属于当前轴配置，不与账号角色仓库混为一页；此名称和呈现位置为提案 |
| 时间轴 | 动作、伤害点、状态/Buff 层，后续可选视频 | 保留编辑上下文；选择记录后用检查面板展示关联效果、条件和来源 |
| 伤害分析 | 总值、贡献、目标筛选、逐点公式、来源及诊断 | 读取同一项目结果，能跳回对应记录，不重复维护计算输入 |
| 内容定义 | 自定义角色、伤害公式、效果定义与预设 | 当前只有有限字段编辑；完整表达式编辑留在 P2/P3 |
| 配装优化 | 目标、搜索变量、约束和结果 | P6 实现前不提供看似可用的搜索；目标范围与变量范围保持独立 |
| 设置与帮助 | 应用偏好、版本、支持范围、验收/开发工具 | 旧自动模拟器与开发入口放在次级工具区 |

建议侧栏分“账号资料”（账号、角色、圣遗物）和“当前轴”（队伍、时间轴、伤害分析）两组，项目切换入口独立保留。内容定义、优化及工具按实际能力另行安排；角色中的武器编辑、是否独立增加武器栏尚待讨论。

## 布局与交互原则（提案）

- 左侧固定、可折叠的一级功能导航；不要同时保留两个竞争的全局侧栏。
- 顶部区分当前账号和当前轴，明确当前页面的保存对象与修改状态。账号保存不冒充轴保存，轴导出不冒充账号备份；切页不会创建另一份项目或丢失输入。
- 中间显示当前功能，右侧按需展示记录/公式检查面板。时间轴编辑时可保留紧凑的目标值与待确认数量，不要求频繁切到分析页。
- Buff/条件主要附着在时间轴记录和来源上，不先拆成互不关联的表单页；是否需要独立“效果与条件”页由后续使用量决定。
- 目标筛选在分析中编辑，时间轴用标记同步显示；两处共用同一目标状态，不维护两个筛选副本。
- 桌面与网页共用导航、路由和项目状态；窄窗口把侧栏收起为抽屉，不另做一套业务界面。
- 未实现能力不伪装可用。远期菜单是否隐藏或显示“未实现”待定；当前默认只展示具有实际可操作内容的入口。

验收增加：桌面/网页导航一致、当前页高亮、侧栏折叠、跨页编辑状态保留、记录与分析双向定位、未保存状态可见、旧工具可达及窄屏操作。另验收账号与轴独立保存、账号更新不改变旧轴、轴内候选改动不覆盖账号实际装备、缺少原账号时已有项目仍可复算。具体状态存储和路由技术在分区确认后决定，不把“参考莫娜”直接等同于必须采用其 UI 依赖。

实际装备编辑补充验收：角色栏调整武器/圣遗物并保存账号，重开账号后配置一致；已有轴保持原快照和结果。轴内修改并保存候选方案后，账号实际装备保持不变。实际圣遗物按实例管理，同一账号的实际装备配置不得让同一件实物同时装备给多名角色；冲突处理方式在 UI 实施前明确，不静默更换其他角色装备。
