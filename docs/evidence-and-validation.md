# 证据与验证

## 来源、独立核验与观测

开发、演示、性能测量和验收使用可追溯的真实游戏内容、合法参数及获授权资料。每项结论按其实际证据层次记录。

| 层次 | 记录内容 |
| --- | --- |
| 来源调查 | 固定版本、原始路径、规则语义、适用条件与许可 |
| 独立计算 | 真实机制下的明确设定、独立推导的期望及容差 |
| 真实资料功能检查 | 原件上的导入、编辑、文件、求值和比较结果 |
| 游戏观测 | 对应配装、目标、时间条件及可追溯录像或伤害画面 |

目录收录、参数绑定、计算支持和游戏观测分别表达事实。共享能力可以复用核验，实体参数与绑定分别确认。功能检查、完整机制和操作可执行性各有对应的验证范围。

每项记录包含来源与取得时间、固定版本、适用对象、条件、用途、独立期望、容差、结果及材料缺口。记录保存在工具资料与运行报告中。多站相同资料须核对共同来源，独立性按实际出处判断。

原件保存在获授权的本地忽略目录，检查直接读取。原件缺失时对应检查明确跳过。格式和错误边界可从实际资料透明派生，记录修改项，派生副本按软件检查用途使用。

理论换装采用真实合法装备参数，持有事实以实际库存来源为准。人工标注、推导和修订分别记录；可确定效果的推导须具备明确初始状态与相关记录完整性。

来源保留精度、单位、标识和有意义的顺序。候选经审阅后采用，普通生成离线；代码与资料复用按确认的许可执行。材料登记见[验证资料](../tools/data/README.md#验证资料与独立计算记录)。

## 测试与验证

结构化伤害系统的验收以公式完整性、全目录覆盖度、独立推导和软件检查为依据。数值检查使用真实目录参数及明确计算条件；实际游戏效果由开发者后续手动测试，实录和伤害观测材料作为独立证据登记。录制原件相关检查缺失时如实跳过，不伪造替代资料。

活跃测试和辅助代码集中在测试目录，按包单元、集成、浏览器、桌面和性能组织。生产实现与测试各自维护入口，通过公开契约连接。

行为修改检查对应回归；机制期望依据来源独立计算。低影响文字与布局变更采用相关内容和实际页面检查。日常验证按影响范围选择，最终交付按冻结源码执行相应矩阵。

涉及角色、库存和战斗的数据遵循[证据规范](evidence-and-validation.md#来源独立核验与观测)。检查直接读取获授权的真实原件，材料缺失时明确跳过。测试目录集中维护操作与独立核对代码，格式和错误边界从实际原件透明派生。

保存、撤销、取消等软件行为可以使用当前空文档；格式错误和边界输入从实际资料透明派生，记录修改内容。性能报告说明实际输入、测量范围、机器环境和材料状态。

浏览器与桌面验收串行、单工作线程运行，使用独立临时资料目录。进程管理依据当前运行创建记录，只关闭已确认归属的实例。

测试入口和命令见[测试目录](../tests/README.md)，界面操作检查见[复查流程](interface.md#界面复查)，交付条件见[交付规范](development-and-delivery.md#构建与交付)。

## 性能测量

性能检查使用真实可追溯输入，记录来源、环境、预热、采样次数、统计方式、实际支持状态与测量范围。原件缺失时明确跳过。

配装求值、时间轴吞吐、界面交互和构建体积分别测量。各报告说明所覆盖的操作与材料状态，性能结论对应实际工作负载。

优化前后使用相同输入及统计口径，独立核对数值与交互行为。浏览器测量包含驱动开销，运行时堆变化按对应进程和采样区间解释；目标平台覆盖按实际执行环境登记。

预算与具体输入见[性能维护入口](../tests/performance/README.md)，测量结果保存在输出目录。
