# 内容、格式与数值规范

正式可维护内容使用严格JSON：UTF-8无BOM、LF、两空格缩进、末尾换行；不允许注释、尾逗号和非有限数。原始采集证据保留来源字节，不强制重新排版。生成分块可以压缩，只能由正式输入重建。

角色的唯一结构是schema/content/character.ts的`CharacterDefinition`。内置与自定义共用校验、渲染、配装和导出流程。每个定义直接包含：

- 身份：名称、称号、介绍、元素、武器类型和稀有度。
- 基础属性与成长：基础值、等级曲线、突破增量、突破属性和静态修饰。
- 天赋：名称与说明、等级参数、说明模板、已核验命中到参数的绑定。
- 被动和命座：文本、解锁条件、结构化天赋加级及各自支持状态。
- 能力：文本与数值收录程度、计算支持及明确原因。

说明模板只替换已声明参数，不执行代码或HTML。角色介绍和技能说明由页面直接读取；命中倍率从同一`parameters.values[level-1]`读取。独立卡片投影只用于轻量列表，不是另一份手写技能表；配装快照中的角色定义优先于最新目录。

武器与套装也各自使用共同schema，静态修饰属于实体本身。ID用于引用，中文名称用于展示；命中、参数、被动和命座标识必须唯一，支持的命中不能引用缺失参数。资源和采集记录在assets及tools/data管理，不要求每个角色重复维护资源来源清单。

比例以小数保存（46.6%为0.466），等级是整数，时间轴使用整数毫秒。源参数保留原精度；单位只在明确边界转换一次。所有数值族及替换依据见[精度审计](../references/numeric-precision.md)。JavaScript使用双精度运算，不声称复制游戏内部float32逐步运算；浮点尾数不等于新增可信精度。

作者只编辑`src/game-data/data`；`pnpm data:build`校验并生成，`pnpm data:check`只读比较。采集和候选更新是显式动作，不能由构建自动覆盖正式JSON。内容版本变化也不能替换既有账号/轴里的数值快照。
