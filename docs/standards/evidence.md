## 什么算真实案例

一个案例必须是可追溯的实际游戏场景：真实角色、命座、技能与机制，真实装备参数，明确的配装、目标条件和操作记录。库存优化还必须有实际账号/公开实际库存来源及实物身份；声称对照游戏伤害或视频时，必须有对应观测资料。

真实角色名加任意攻击/倍率、捏造Buff或圣遗物、拼凑伤害序列、构造扫描器格式文件、引擎自算的“标准答案”，都不能替代这些资料。没有玩家数据时，不得把游戏静态目录或自动化测试导出的文件称为玩家账号。

独立公式核对与游戏实测对照分别记录。合法参数下的公式核对可以证明计算一致性，不能据此声称已完成实测或实际库存验收。

## 全角色覆盖的证据分层

P5按[全角色计划](../planning/p5-character-usability.md)推进，不能只用一支队伍宣称全部角色可用，也不要求每位角色先取得完整实战录像才能开展机制调查、实现及独立核验。

| 层次 | 依据与用途 | 可得结论及边界 |
| --- | --- | --- |
| 来源调查 | 正式参数、固定版本机制资料、社区实现及许可核对 | 确定规则设计及采用范围；目录存在或上游已实现不等于规则正确或本项目已支持 |
| 独立计算核验 | 可追溯真实机制及数值、明确合法计算配置、独立推导与容差 | 证明对应公式、参数绑定及条件下的一致性；明确配置是计算设定，不伪装成玩家原配装或实际轴 |
| 真实资料功能检查 | 获授权实际配装、库存、项目及记录，缺失字段保留未知 | 证明该资料上的导入、编辑、求值、比较或优化行为；不能推断其它角色或全部机制通过 |
| 游戏观测对照 | 对应配装与条件的录像、伤害或其它可追溯观测 | 证明明确观测范围内的对照；没有观测时不得声称实测通过 |

每个角色或形态分别登记基础路径、机制及版本、独立核验、真实资料检查、游戏观测和缺口；共享通用机制的核验可复用，角色参数及绑定仍逐项核对。按真实机制和来源进行显式计算不授权新增虚构Buff、任意倍率、伪造玩家导出或合成战斗序列。

缺材料时先在已有授权原件和可追溯公开资料中查找，记录缺什么、影响哪项结论。可以继续不依赖该材料的工作；缺件检查明确跳过，不能计为通过。没有录像不否定已有依据的公式核验；核心机制缺失或必要集成未完成也不能靠声明缺口取得P5完成状态。

## 每例必备资料

| 项目 | 记录要求 |
| --- | --- |
| 身份与用途 | 案例ID、真实使用任务、覆盖阶段/机制、材料负责人、当前状态 |
| 来源 | 原文件/公开链接、取得时间、固定版本或哈希、可使用范围；玩家标识脱敏，原件按授权保存 |
| 角色与配装 | 等级、突破、命座、天赋、武器/精炼、每件圣遗物原始主副词条及实物ID；缺字段不猜测 |
| 轴与目标 | 原始动作/命中时间与同刻顺序、目标集合、敌人等级/抗性/阶段、暴击/反应等明确事实或未确认项 |
| 机制依据 | 固定本地参考、原始机制来源及适用版本、触发/覆盖/捕获/历史或概率条件、支持边界 |
| 独立期望 | 从来源数值独立手算或独立实现得到的单点、效果、目标；含推导和容差，不调用待测引擎造期望 |
| 观测证据 | 若有，记录录像时间点、画面/日志伤害和误差解释；没有则明确“未做游戏实测对照” |
| 操作验收 | 用户任务、实际UI步骤、是否需技术知识、问题/修复、截图/记录、保存重开与CLI复算 |

不建立tests/fixtures或其它固定输入归档目录。真实原件保存在获授权的忽略位置.references，测试直接读取已有原件，缺失时明确跳过依赖检查；文档只说明取得方式、用途及观测边界，不复制原始记录或生成替代资料。

## 派生、独立校验与性能检查

- 换装对照来自该账号实际可用装备，记录替换了哪件及其原始值；理论配装如另行支持，使用真实合法参数并单独标识，不能伪装为实物。
- 边界/非法输入测试以真实项目副本为底本，标明唯一改动和预期错误；不创造虚构角色、机制或伤害真值。
- 小范围穷举保留真实库存原始ID、词条和合法性；候选范围固定后独立枚举。全队目标必须重求队友效果，不能把单人静态分数相加当真值。
- 压力检查先使用实际项目/实际库存规模。需要比较重算吞吐时可重复求同一真实项目，说明计量方式；不得把复制出来的轴或假库存称为真实场景。
- 历史合成场景及专用测试已删除；当前及后续行为、演示和性能证明按本规范提供真实来源证据。软件格式和错误边界派生检查必须明确用途，不能冒充玩家导出或观测。
