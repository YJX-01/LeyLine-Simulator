# 文件与状态边界

账号、轴项目和内容定义分别保存。导入失败、取消或格式不支持时保持当前编辑；保存原生文件对话框期间继续编辑时，只将实际写出的快照标记为已保存。

角色、账号、项目和定义库当前封装版本为2。项目规则为`timeline-v1`，配置为`direct`或`dependency`。本轮是破坏性重构，只接受当前契约；旧版本文件直接拒绝，不转换或升级。

2026-11-14新增用户明确要求的独立伤害计算器文件：kind为damage-calculator、schemaVersion为1，内嵌当前项目及可选比较基准，仅保存独立计算设定和快照。文件最大8MiB，不包含账号写入操作，也不使用旧轴文件的迁移或回退；保存结果数值不作为重开时的真值，重开必须经同一Worker重新求值。契约与候选隔离见[查询覆盖及候选复算](../architecture/query-damage-coverage.md)。

当前项目新增kind=capture的独立属性取值记录，保留当前项目版本，必须关联队员技能及无公式、无效果定义，不能作为施放或伤害。来源技能、时间和同刻顺序随文件保存，Worker／候选从原时刻重算。读取账号中的未完整角色时保留实物引用，缺培养／武器由计算副本补全，不借展柜补成本地事实；显式审阅后更新计算副本内容与打开文件是两项操作，后者不自动更新定义。

账号、恢复副本、角色配置、队伍与定义库只读取各自当前v2存储键，不回退读取旧键。代码清理保留磁盘文件及已有浏览器记录；当前版本的正常新建、替换前备份和恢复操作继续有效。角色元数据文件保持直接根对象。

本地账号拥有实物库存。公开展柜是独立快照；查询、取消与预览不写库存。确认默认为导入并合并，用户可选择仅快照。匹配包含套装、部位、星级、等级、主词条和值及有序副词条；这是用户确认的内容匹配，不证明游戏实例身份。已核验展柜强化历史优先于本地推断，已有物品ID和穿戴保持。

角色培养与配装只保存身份、等级、突破、命座、天赋、武器和装备，不保存当前生命、能量或战斗状态。2026-11-13起，项目combatStates可按队员和时间区间记录生命比例、站场与护盾存在状态；具体命中按字段显式覆盖，范围及优先级见[战斗状态契约](../architecture/combat-state.md)。damage.conditions仍表示命中所属队员的覆盖，stateOverrides可按队员指定本次上下文覆盖。生命比例范围0至1；缺失继承区间，显式null阻断继承并保持未知。展柜导入不要求也不读取fightPropMap，不将展柜状态当作战斗条件；重新导入账号不修改轴内标注。

添加队员不自动创建目标；目标设置保持原有用户已确认的界面交互，不因本次数据重构增加按钮或新流程。90级与10%抗性只可作为表单初始计算假设，不作为已确认或观测条件。新伤害点的暴击、反应默认未确认；生命门槛在计算契约中保持显式条件，界面调整需单独获得用户指示。

配装契约已移除旧 `hpRatio` 字段；按本次破坏性重构规则，含该字段的旧文件不转换，严格校验时拒绝。代码不清理已有文件或浏览器记录。

不得静默合并不同账号。Mona导入或角色配置不自动保存独立圣遗物组合；保存组合是明确动作。删除库存时保留已穿戴、配置和组合的脱库快照，去除库存身份并显示未持有；不能重新创建实物。候选队伍、内容定义修改也不反写账户。

导入适配细节见[Enka](../references/enka-import.md)与[Mona](../references/mona-community.md)。日常UI约束见[界面规范](../design/visual-language.md)，证据规则见[证据规范](evidence.md)。

读取当前账号草稿失败时，保持原始缓存字节；空账号的自动保存或普通编辑不得覆盖它。用户显式打开、新建或恢复账号时，先按原有替换前备份机制保存原字节，备份失败则不替换。此保护不转换、不迁移旧格式，也不新增界面流程。

## 圣遗物共享引用

本地账号的 `artifacts` 保存物品，角色 `equipment` 保存部位到物品 ID 的引用。同一物品可被多个角色、首选／备选配置和组合引用，校验引用存在及部位一致，不限制角色间唯一归属。选装、采用配置、应用组合只更新目标角色；草稿仍需保存。

展柜“同时导入本地库”经确认后合并物品，并用对应本地 ID 完整替换所选角色的五部位引用；缺少部位清空，旧库存保留。其他角色与保存的配置／组合不随之改配装。仅保存展柜、详情内单件入库以及组合编辑均不触发该同步。
