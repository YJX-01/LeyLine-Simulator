# 产品方向

产品围绕真实配装管理、伤害核验和同轴换装比较展开，进一步服务于明确库存及约束下的全队优化、概率分析和录像复盘。账号、轴项目、内容定义库分别拥有数据与保存流程。

伤害功能优先让独立计算器覆盖正式目录全部角色与形态的每个伤害段和每项增益。玩家给定配装、敌人与当次战斗条件即可计算。武器、套装、队友与公共效果随计算依赖接入。自动推导战斗时序和实际贡献分析随后推进。具体进展按[支持判定](calculation.md#计算支持判定)维护。

依赖层数、次数或累计点数的单击伤害属于当前范围。计算器预填合法数值，玩家可以直接填写本击采用的数值，再按所选暴击方式计算。

[锁面板](calculation.md#锁面板)作为独立机制跟踪。缺口按受影响的命中段登记，优先级低于单击计算的核心问题。

需要汇总多条伤害记录并逐条判定暴击，或需要展开多个贡献者的暴击组合才能得到总伤害时，相关开发和整体验证**暂缓**。

圣遗物实物的当前支持范围为四星与五星，低于四星的实物处于暂缓状态。低星武器按其实际规则维护。

通用伤害和反应算法固定在TS中，角色JSON维护数据、缩放、条件及效果配置，可选动作JSON维护时序。新增机制超出现有模板能力时更新引擎；不以任意JSON运算图或脚本扩展算法。

用户在可运行应用中录入配装。来源调查和独立公式用于验证试算数值，战斗和换装观测用于核验实际表现。各类材料按[证据规范](evidence-and-validation.md#来源独立核验与观测)登记。

动作、命中、反应归属及必要外部事实由明确记录提供。确定效果的推导以初始状态和记录完整性为前提；人工事实与推导结果分别保存。

候选比较固定原轴并独立重算。伤害变化、充能、攻速和持续时间等操作可执行性分别评估。独立伤害计算入口拥有自己的配装和比较基准，复用共同求值器。

界面沿用已确认的主题与交互。产品增量按明确需求实施，设计调整通过具体方案审阅确定。
