# 界面设计与复查

## 视觉与交互规范

界面沿用用户确认的主题、页面组织与交互。新增页面复用语义颜色、文字层级、控件及编辑流程，设计调整通过具体方案审阅。

### 颜色与排版

基础色板按元素划分原色、浅色和深色；中性色表达画布、内容、正文及分隔。原色用于图形与边线，浅色用于分组和选择，深色用于文字与实色操作。深字浅底及白字深底的对比度至少为 4.5:1，游戏美术保留原色。

保存与采用使用主要确认语义，删除、取消和还原使用危险或撤销语义，本地与展柜使用各自来源色。相同状态复用相同语义变量。

| 文字层级 | 字号与字重 |
| --- | --- |
| 页面标题 | 24px、700 |
| 弹窗标题 | 20px、700 |
| 分节标题、编辑与常规操作 | 16px、700 |
| 正文、标签、提示和普通数据 | 至少 14px |

全部可见文字共用系统界面字体，标题、数字、代码和许可文本沿用相同字体栈。字重按既有层级使用，拥挤布局通过换行、列数、宽度和间距适配。

### 控件与图像

控件外框高度分为 40、32、24px；同排工具保持同高。相连控件按边框和内距计算内部高度，内容型卡片按内容排版。常规圆角为 7px，间距沿用共同尺度。

图片与图标上的短等级、命座、精炼和件数角标使用明确标记，标准档 12px、微型档 10px。正文状态、主要数值和强化统计采用普通文字尺度，角标宽度随数字增长。

图像保留等比构图、稀有度语义和可访问名称。装饰使用独立资源，继承语义颜色并让出点击与朗读。

### 编辑与反馈

编辑先使用草稿，保存、另存、还原和放弃各自表达明确操作。保存状态、按钮状态与内容变化承担操作完成反馈，校验错误和冲突确认位于既定位置。

未保存退出提供保存、继续编辑和放弃修改；保存成功继续原导航，失败保留草稿。关闭确认与退出键回到继续编辑。

弹窗共用标题、操作区、关闭和底栏。子弹窗拥有当前焦点，关闭后返回入口；遮罩从按下至释放均命中时才关闭。列表和选择弹窗复用控件，分别保存各自浏览状态。库的五个子页共用空列表样式。库中还没有资料时，在列表内提供新建入口。已有资料经搜索或筛选后没有结果时，提供清除条件入口。

角色配置和圣遗物卡默认采用紧凑密度。角色配置列表每页最多五排，容量按当前列数计算。查看详情的卡片共用固定上边缘。鼠标悬停、按下或键盘聚焦时，仅上边缘变为风元素绿，卡片保持原位。选择或替换使用水元素蓝。鼠标悬停在替换区、键盘聚焦或触屏按下时，蓝色遮层覆盖图片、套装件数和等级角标。双箭头在整个替换区水平、垂直居中，图形上下贴合自身边界。同时提供详情和替换的卡片，点图片区替换，点正文或留白查看详情。只读卡整卡查看，空槽点按选择。

角色详情与培养页聚焦培养及装备，内容说明用于定义编辑、计算和导出。页面与组件的具体尺寸、选择行为、收藏及导航约定见[交互契约](../src/web/README.md#已确认交互契约)；色值与控件入口见[界面实现](../src/web/README.md)。

手动添加角色选定身份后，直接使用角色详情编辑器。培养、武器、五个圣遗物槽和有效词条共用一份草稿。武器槽可留空，顶栏使用共用的「保存」和「还原」。展开的角色面板随草稿更新，完整配置名在配置卡上显示。队伍中已有队员的配置弹窗，顶栏从左到右为「切换其他角色」「移除队员」、标题和关闭。点「切换其他角色」进入带「本地｜全部角色」的第二级，关闭后回到原队员的配置列表。空槽直接打开选人弹窗。

角色配置和队伍的列表卡在标题行右侧显示收藏等级，筛选器支持未收藏和一至三级多选，排序器提供「收藏等级」及两个方向。

## 界面复查

以已确认页面和[视觉规范](interface.md#视觉与交互规范)为基准，按改动所涉及的真实资料路径复查。

1. 明确页面、数据归属和预期操作，等待页面及资料加载完成后查看实际布局。
2. 使用真实来源完成输入、选择、保存、还原、取消和退出，分别核对草稿与持久状态。
3. 数字框逐键输入，检查中间编辑态、提交归一化、等级边界及命座加级。
4. 点击字段名称核对输入聚焦，检查图标的可访问名称、键盘导航和可见焦点。
5. 检查嵌套弹窗的初始焦点、关闭后的焦点返回、退出键顺序、遮罩与边框、滚动隔离及未保存退出。
6. 检查窄屏、长名称、完整数字、减少动态效果偏好，以及工具栏、卡片和弹窗的实际计算样式。
7. 运行相关回归，核对错误日志和截图；交付桌面时串行检查当前隔离实例。

布局测量等待边界稳定后进行，视口与滚动条按实际渲染尺寸取值。功能流程、设计审阅、软件验证和游戏观测分别记录结论。

复查工具补充视觉、键盘和操作检查，项目规范与用户决定作为取舍依据。具体命令见[测试入口](../tests/README.md)，截图和测量结果保存在运行报告中。

### 界面的其他原则

1. 不要使用中点 “·”作为文案的分隔符。如果有，移除它。
2. 不要在界面添加冗余的解释性描述文本，这会弄脏 UI 界面，还会浪费用户的注意力。
3. review 界面文案，尽量使其描述符合当前界面面相的人群，容易理解但不要过于口语化，长短适合其功能场景，不要冗余和随意造词。
4. 优化界面元素与 UI 的对齐效果，尽量做到光学对齐；有嵌套的地方，尽量做到同心圆圆角处理。
5. 尽量减少页面出现需要用户判断才能进行的交互；必须发生时，放在用户本来就打算做选择的地方。同时，重新思考页面中包含的功能和元素，判断信息优先级，使用更有秩序的做法进行组织。
