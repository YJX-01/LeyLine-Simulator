# P5命中条件界面评审稿

2026-11-14。对应[P5唯一详细计划](../planning/p5-character-usability.md)的R1评审出口。本文是具体控件提案，不是另一份实施计划。用户本轮明确要求侧栏独立计算器，计算器在该授权内实施；下面对既有时间轴“记录详情”的增量仍待用户审阅，未添加到角色详情、培养页或时间轴页面。

## 位置与操作

保留时间轴右侧记录详情、现有目标条件弹窗和队员候选编辑。选中真实技能命中后，“命中条件”放在当前暴击／反应位置；按本条命中的正式定义展示所需字段。普通文字14px，字段40px，分节16px，沿用现有主题，不增加诊断区、介绍、第二套工作台或操作成功通知。

| 字段 | 具体控件与显示 | 写入边界和缺值 |
| --- | --- | --- |
| 反应 | 下拉“待确认／无反应／本次元素允许的已实现反应”；归属显示当前命中角色 | 仅写当前命中reaction；蒸发、融化、超激化、蔓激化按正式规则求值，不推演附着历史；未知触发者仍未知 |
| 生命／站场／护盾 | 当前角色生命百分比、三态“待确认／是／否”；队友切换后单独编辑 | 当前命中覆盖与已录区间分开；明确选择“采用区间”才删当前覆盖，不能把空值解释为否；培养资料不携带这些战斗状态 |
| 反击／层数 | 按技能显示中文名称与合法范围；北斗“待确认／0无加成／1一档／2满档或完美反击” | counterCharge为已经确认的反击档位，不声称是受击次数；空值仍未知，不自动选零。其它技能使用来源声明的整数／小数范围和命座上限 |
| 属性捕获来源 | 下拉条目“角色 · 技能 · 秒数”，再选“记录生效前／后” | 只列同角色、合法来源技能的明确记录；无记录保持待确认。R2独立取值点契约和计算器输入已实现；本表仍是既有时间轴控件提案，不移动施放、不伪造动作来补捕获 |
| 来源效果适用 | 仅列此命中所需的适用事实，行名“来源角色 · 技能／武器 · 施放秒数”，三态“待确认／适用／不适用” | 引擎生成并验证instanceId，用户不填写；换装、来源删除或版本变化后保留待核对，不能换绑到相似效果。固定值修订不解除未实现规则 |

来源选择的示意文字只说明标签格式，不构造玩家轴或预设伤害。真实使用从用户已有记录选择。效果冲突、未知和未支持保留现有结果位置；不在角色面板追加诊断小字。

## 推导与修订

可以确定的状态和消耗应由引擎推导。次数／冷却接入时，在对应来源记录编辑必要的“轴前初始状态”和“相关记录是否完整”，而非要求用户逐命中判定。两者未明确时不能以“没有记录”为零消耗或未触发。人工事实、推导结果和人工修订分开保存，推导与修订只计一次；来源改变后先核对。

当前R1计算器已提供单点配装、暴击、反应、生命／站场／护盾、技能数值输入，以及复制轴后的已有捕获记录选择。新建计算不自动生成施放或连续攻击。锁定基准后只改配装，命中和敌人字段锁定；“结束对照”后再改这些条件。计算器没有把尚未实施的次数、冷却或独立捕获推导伪装成可用控件，也未新增来源适用事实编辑器。

R2增量在用户授权的计算器内增加“命中时刻（秒）”“独立捕获时刻（秒）”和添加捕获点操作；捕获来源仍以角色／技能／时刻显示，阶段必须明确。独立捕获秒数初始为空，不采用延迟默认值，不推导施放或命中。资料来源包含缺Build的本地角色，保留穿戴后在计算副本补全；“检查当前内容”列出定义变更并明确采用，取消不更新、比较时禁用、自定义角色拒绝替换。上述控件没有添加到角色详情／培养页或原时间轴。
