## 结构化角色导入事务

domain/structured-character-import.ts 提供角色 JSON 的准备、预览副本、应用与导出。prepareCharacterImport 校验当前元数据契约，装配本机公共依赖并编译，缺依赖或模板时报错。Prepared 保存本次准备的数据，由调用方显式确认后提交。

结构化角色导入只接受数据配置和已注册TS模板的精确版本；文件中的运算节点、签名覆盖、脚本和旧计算库拒绝。离线复算使用文件数据与匹配运行时算法。

准备阶段同时递归核对角色自身效果和属性基数中的技能参数。缺参数或单位不符时返回具体绑定的JSON Pointer，当前注册表保持原值；这类定义错误不作为待用户补充的战斗事实。

外部builtin声明只可复用已注册的相同快照。新增内容使用独立custom命名空间；外部证据按declared处理，已与本地注册内容完全相同的共享记录可复用。相同完整身份的角色、公式、效果或来源内容冲突时阻止应用；修改命名空间或修订后须重新准备。注册表发生任何变化，旧准备结果失效。

applyCharacterImport 返回新的独立数组。exportCharacterSnapshot 检查可达定义，再把角色参数、专属效果和曲线引用写为两空格缩进的 JSON。计算器将导入的角色定义应用到自身项目并重新求值。

domain/structured-actions-import.ts提供可选动作文件的prepareActionsImport、preparedActionsSnapshot、applyActionsImport及exportActionsSnapshot。它精确关联所给角色，复用同一引擎编译与闭包；builtin外部声明只能复用已知相同内容，同一身份的定义/来源冲突拒绝。角色或当前动作变化使Prepared失效，预览和应用返回独立副本。当前入口为离线域事务。

## 地脉工作台使用说明

桌面双击artifacts/desktop/Start-LeyLine.cmd；开发网页在仓库根执行pnpm dev。网页与桌面使用同一工作区。

账号资料、队伍、轴项目和独立伤害计算分别保存。浏览器草稿用于恢复，请按需要另存文件。站点域名、协议或端口变化前先导出资料。

### 角色与装备

侧栏“角色”管理本地培养和展柜。点击角色卡进入详情，点击头像定位培养输入，点击武器选择装备，数值编辑后保存或还原。本地与展柜切换各自来源。

“展柜导入”输入UID后查询、预览勾选再确认，默认导入并合并，可选仅快照。账号UID可在“账号”中维护。角色和物品来源在确认时核对。

“圣遗物”支持Mona文件、JSON粘贴及手动创建。预览后确认入库，物品详情提供编辑、另存、收藏及删除。另存创建新ID，原件和引用保留。

选装单击物品进入角色草稿，保存后生效。同件物品可被多个角色及方案共享引用。删除库存后已有方案保留脱库内容并显示未入库；应用时明确入库或替换。

“角色配置”保存首选与备选，“圣遗物组合”独立保存五部位和统计口径。保存组合先进入草稿，保存后建立记录；应用组合更新目标角色草稿。比较在详情内选择另一份方案，两侧保留各自统计基准。

### 队伍、轴与独立计算

「库 → 队伍」按队伍名或队员名搜索，可组合筛选包含角色和收藏等级。默认按保存顺序从早到晚，也可按队名或收藏等级排序。默认每页五支，上下均可翻页。

「项目 → 时间轴」可命名、打开和保存轴，「更多」提供新建空轴、重新计算和恢复上次编辑。时间轴可记录动作、场景效果、附着/反应观测、技能治疗、待建模命中及明确伤害输出，可调整时间、同刻顺序、目标与条件。轴文件可携带明确聚合反应和动作状态输入，打开后经 Worker 求值。「伤害分析」按全轴和已勾选目标汇总伤害，点击伤害点定位到时间轴。

#### 试算一次命中

顶栏下方先选择队伍与角色。队伍库、选择弹窗和已选队伍使用同一头像尺寸。选择队伍会复制保存的队员配装，角色弹窗随即只展示这支队伍的成员。单人计算在角色弹窗选择本地、展柜或游戏目录。游戏目录复用角色库的手动添加流程，保存后使用该角色的本地配置。本地角色详情沿用角色库的「保存」和「另存」，当前计算随保存的配置更新。已选角色复用配置卡的角色、武器与套装三联图。点击三联图片区域更换角色，点击卡片其余区域打开角色详情。展柜、队伍、导入文件和对照试配使用计算快照，详情的「保存」更新计算，「另存」走角色库的配装保存流程。无实物引用的装备以未入库快照保留。

「选择伤害」把角色已指定的常用分段置顶，其余按实际伤害类型分组，每个分段只出现一次，不含时间轴场景冲击。分组可展开或折叠，默认顺序和展开状态取自角色 JSON。没有指定顺序时展开首个有条目的类型。主页与选择页共用伤害卡。左侧显示来源图标和编号，下落攻击依次标为 x1、x2 等。右侧三排依次为别名（正式名）、备注、倍率；没有备注时保留第二排。搜索编号、别名、正式名、备注或天赋名时会展开匹配分组，清空搜索恢复先前的折叠状态。卡片按当前配装显示单击倍率，涉及多个属性、段数或层数时分别列出。可选分段取决于角色突破、命座和装备。选定分段后会带入它唯一要求的姿态或元素状态，同时在后台预置满血、站场、无盾默认事实。剧变反应图标组合参与反应的元素，碎冰显示冰与物理。独立扩散只占一张卡，队伍中只有一种可扩散元素时预选该元素，其余情况预选火，可在「命中条件」调整。仅当所选伤害存在轻量化条件（反应、星辉状态、转化元素、队伍附魔、自身附魔、扩散元素、星扩散伤害段、技能专属输入或命中序号）时显示「命中条件」分组，切换下拉选项即刻重算，数字输入保持平顺并在提交变更后重算。技能层数、次数或点数从该输入的合法下限开始，可直接改成实战值。

烟绯的重击按本次消耗的丹火印选倍率，第四枚需要六命。香菱等角色的同倍率多击会显示总击数，可记录本次为第几击。计算文件保存所选序号，每次求值得到这一击的伤害。

主页以图标并列展示已选战斗伤害增益。伤害计算页仅列举直接影响本次伤害的增益效果，排除探索与生活效果以及非伤害向机制条目。打开「选择增益」，可按别名、正式名或来源搜索。卡片先列已选增益，再列当前命中直接用到的效果。勾选和编辑期间卡片位置固定。在同一张卡上勾选效果、调整层数或适用的生命比例。需要手动触发的增益默认关闭。勾选时，卡片会带入触发条件和适用的生命比例。标有「勾选取满层」的增益在未给定正层数时取上限。多张卡共用同一队员或目标的同一个条件，修改一处会同步显示。主页已呈现的条件不再重复列于「本击条件」，仅当存在其余本击条件（且生命比例、站场、护盾存在至少被一个可用伤害增益引用）时才展示对应输入或「本击条件」分组。点击「应用增益」后，条件和需要补入的施放记录写入计算副本并立即重算。

需要捕获属性的命中在后台由 `reconcileCalculatorHitState` 与 `prepareCalculatorEvaluationProject` 静默绑定最近的合法同技能记录或事件前快照，不再展示时间轴捕获表单或时刻控件。

队伍、角色、伤害和增益按两行两列排列。伤害页四槽无论空置或已选，桌面均高 140px，窄屏均高 114px。鼠标移到已选伤害上时，整张卡面会变色，点击可更换伤害。队伍编辑页按当前宽度预留完整配装卡的高度，选择、更换或移除队员时四个槽位保持原位。宽卡的词条在头像右侧，窄卡的词条在头像下方。空槽沿用「新建组合」的圣遗物卡面，居中显示加号和选择文字，队员空槽另有人物图标。选择队伍角色中的已有记录、选择伤害、应用增益、保存配装、重开已保存记录或打开计算文件后会自动协调并立即重算。

结果栏左侧显示暴击伤害整数，右侧显示一位小数的期望伤害，同时由 Worker 分别求值暴击与期望两种口径。选择奥黛塔的星烁追加段时，计算器沿用合法辉映选项并默认星超导，可在「命中条件」切换有效的辉映状态。

每个乘区独占一行，可单独展开。展开属性 × 倍率区可左右对照基础属性和倍率，附加基础伤害（羽毛）与反应基础加值列在下方。反应直伤的基础伤害明细列出本击采用的属性、天赋倍率和反应系数。反应基础倍率区显示基础加成及其直接来源。暴击区显示期望倍率 `1 + 本击有效暴击率 × 本击暴击伤害`，展开可分别核对两项属性的来源。星反应增伤区分列元素精通折算的百分比和反应伤害加成，下方显示两项代入后的倍率。彩色分项卡仅列出有贡献或数值尚未确定的加成。

角色配置区显示候选角色的实时面板与五个圣遗物槽。页底的「怪物属性」设置等级、八种基础抗性、减防和无视防御，抗性按百分数填写。

「伤害计算」顶栏左侧的「伤害列表」打开本机记录，右侧的「保存伤害」保存当前命中。每次保存一份独立快照，列表按保存时间倒序，可打开或删除。IndexedDB 按应用版本命名，摘要写入暴击伤害、期望伤害与兼容展示值，与完整计算文件在同一事务写入。打开列表只读摘要，同时展示暴击与期望数字（旧条目仅含单值时回退显示伤害值），点选条目后由 Worker 重算。

候选比较保持原基准与当前副本在记录、条件和定义上的一致性（对比期间仅更新候选配装），求值时分别对基准和当前候选各自构造临时评估项目并计算暴击与期望。对照表同时展示「暴击伤害值」与「期望伤害值」的基准、当前候选和差值。「导出计算文件」将队伍身份、双方配装和引用的内容集中写入同一个文件，重开由 Worker 求值。切页或打开另一条伤害会保护未保存的编辑。结束比较后可导出角色定义副本，编辑参数并导回当前计算项目。

#### 独立反应与附魔

在伤害选择器中可新建独立剧变、月曜或星扩散反应。计算文件保存触发角色、反应设置、条件和选定增益，计算器与时间轴重开后交给同一 Worker 求值。

近战武器的物理攻击可选择已由队伍授予的本击队伍附魔，已解锁自身附魔的招式也可在「命中条件」切换自身附魔。所选元素同步更新可用反应选项、重置不兼容反应并作用于目标抗性。时间轴场景冲击、附着/反应观测与技能治疗等时序机制保留在「项目 → 时间轴」中处理。

### 草稿与退出

保存、还原和退出确认分别处理当前草稿。未保存退出时选择保存、继续编辑或放弃；取消或无效文件保持当前内容。

### 侧栏与库页

「库」依次为角色、角色配置、圣遗物、圣遗物组合、队伍。「项目」依次为伤害计算、伤害分析、时间轴。账号和设置固定底部。库页与项目页共用画布、页面外框和操作控件。「自定义」页面暂时撤下，内容定义文件契约与存储保留。

主页与选择弹窗共享展示组件，各自保留搜索、筛选和排序状态。会话浏览状态按账号隔离，收藏筛选按账号保留；角色、配置、组合和队伍的页码按账号保留于会话，配置、组合和队伍的搜索、筛选保留于会话。重置筛选和重置排序分别操作，“清除条件”同时清除搜索、筛选与排序，配置恢复全部角色。

库页主工具40px、16px粗体，动作自然宽度、左右12px内距。角色、配置和圣遗物提供快捷工具行，窄屏按共用布局换行；组合和队伍的数量栏紧接主工具。五个库页共用 `LibraryEmptyState`，角色、配置和圣遗物的空列表在相同视口下对齐数量栏、提示和新建按钮。库中没有条目时，列表内的加号打开对应的新建弹窗。搜索或筛选没有结果时，可直接清除搜索与筛选。列表卡按实际容量排版，角色卡目标最小312px、伸展上限360px。滚动条空间稳定预留。

角色分组固定为普通角色、空/荧各形态、奇偶各形态，再按选择方向组内排序。目录默认实装版本从新到旧，角色当前首选按有效条数排序可选。角色配置的排序首项是有效词条数，默认降序，同分时首选排在备选之前。圣遗物组合默认有效条数降序。套装先最高星级降序，再实装版本及ID降序，未知身份置后。

筛选同组任一、跨组同时满足，副词条可选全部或任一；空集合为不限。星级复用RarityFilter，按五星至一星列实际目录星级，黄紫蓝绿灰对应共享稀有度。多选菜单占正常布局，内部滚动，标题和底栏固定。

五个库页均在数量栏及列表底部提供分页。默认每页角色 5 行、角色配置疏松及紧凑各 5 行、圣遗物库存疏松 5 行及紧凑 8 行、圣遗物组合 5 行、队伍 5 行。设置页可分别调整这些行数（1 至 50）并恢复默认；偏好保存在浏览器中，不写入账号或项目文件。角色、配置及库存的每页容量按行数乘实际网格列数计算，尾页显示剩余条目。选择弹窗保留各自的分页容量。视口高度变化时正常滚动，列数、密度或设置行数变化时保留原浏览项附近位置。删除和筛选夹紧页码，空列表保持合法 1/1。手机元素四列，更窄时三列，部位三列两行。

### 角色与配置

角色主页展示每位角色首选，完整配置集中配置页。卡片保留培养、武器及A/E/Q天赋和结构化命座加级；就绪/缺失及展柜状态按原有图文呈现。角色说明与支持诊断归内容编辑、计算和导出，详情与培养页聚焦培养装备。

详情角色名居中，顶栏依次排列收藏、备选配置的图钉和配置下拉按钮。按钮显示由有效条数、套装和武器组成的配置名，按钮宽度上限为 240px。切换弹窗中的配置名也限制在 240px 以内。两处都随可用空间收窄，超长时单行截断并显示一个「…」，悬停可查看全名。本地/展柜为32px分段切换、内部26px。角色卡的套装、角色和武器图共用水平中轴，标准宽度为88、104、88px，空间不足时按比例缩放。两件套图从左上至右下沿对角排列。件数放在套装图左上，精炼放在武器图右上，两者按装备区域尺寸使用同档角标。天赋36px，命座按钮40px或窄屏32px。空武器在主页采用轮廓占位，详情提供加号入口。

角色配置列表第二排用库页共享快捷按钮提供「全部角色」和「选择角色」，右侧是密度切换，同排控件外框40px。「选择角色」打开可搜索和筛选的角色选择弹窗。疏松卡首排标题、培养和动作，次排64px角色/武器及五件紧凑卡，末排七类词条数。紧凑卡缩小角色和武器图，复用角色页套装图和件数角标，七类词条分行排列。紧凑卡按列表实际宽度排为一列或两列，密度保留于会话。首选用火深色、备选用岩深色。整卡单击或键盘打开，右键及 Shift+F10 提供查看、设为首选和删除，首选卡菜单将「已是首选」置灰。角色详情中的选择列表以绿色上边缘标出当前配置。点击备选卡或详情顶栏的图钉，或在配置右键菜单选择「设为首选」，立即采用该配置并将原首选保留为备选。图钉悬停和键盘聚焦时使用风元素绿色。详情中有未保存的修改时，先处理草稿。

清除属于草稿。删除首选时按保存顺序由首个有效备选接替，该备选从备选列表移为首选；清除备选只处理该项。首选、备选和展柜都为空且保存后移除角色，库存保持；失败回退备选变更并留草稿。采用配置和选装只更新目标角色引用。

### 队伍

列表显示队伍名和居中的角色头像，头像沿用角色卡的元素、命座及等级角标。队员名保留于搜索和可访问描述。包含角色筛选复用单选下拉。关闭弹窗保留列表条件、页码与滚动位置。

新建与详情共用编辑弹窗。详情顶部左侧是保存、另存、还原和删除，标题居中，收藏和关闭在右侧。名称输入与自动命名共用组合编辑的40px控件。自动名按槽位顺序用「 / 」连接队员名，新建默认使用自动名，保存后保留填写或生成的名称。

四个槽位可独立选人。队伍文件保存槽位、配装快照及配置来源。桌面槽位排两行两列，窄屏排一列。队伍详情始终可编辑，紧凑卡显示配置名，以快照白值折算词条。图标组与词条并排时，替换热区与词条区等高。点已有队员的图标组，弹窗直接列出该角色的本地配置。顶栏从左到右是「切换其他角色」「移除队员」、标题「选择角色配置」和关闭。点卡面其余位置查看来源配置，原来源缺失时可查看队员快照。右键和 Shift+F10 保留快捷菜单。

「切换其他角色」打开第二级「选择队员」，空槽直接进入这一级。顶栏提供「本地｜全部角色」，有本地配置时默认「本地」，否则默认「全部角色」。两个来源各自保留本次选择的搜索和筛选。关闭第二级回到原入口。「本地」复用角色配置列表，可选首选或备选。仅有圣遗物的配置会打开对应配置详情，保存角色培养后可以回到原槽位继续选择。武器槽可留空。「全部角色」选中后复用手动添加的角色详情编辑器。已有本地培养时可直接选用，也可编辑后保存。「保存」先写入角色库和首选配置，再将快照填入队员槽。之后放弃队伍草稿仍可在库里找到已保存的角色。

保存保留记录 ID，另存使用新 ID 并从未收藏开始。收藏写入已保存的队伍，名称和配装草稿各自等待保存。删除先确认，仅涉及选定的队伍记录和它的编辑草稿。

### 圣遗物、组合与比较

手动圣遗物录入由套装约束合法星级与部位；星级属于实物身份，仅新建可选，四星强化上限16。主词条展示、导入、配置/组合和比较按携带的星级表快照读取；有效条数白值及冻结策略保持原决定。

疏松卡图片112px，与主词条及四行副词条对齐，图文间距10px、名值间距12px，最小列宽280px、外框至少132px。紧凑图64px、四行实际副词条、14px粗体、图文间距8px、内距6px、最小列宽192px，主属性图标在左上。库存首次打开为紧凑，手动切换后记住偏好。角色配置列表首次打开为紧凑，密度选择保留于会话。选装、队员和其他引用卡片各自默认紧凑。

图像左下佩戴者20px，右下强化；脱库及未匹配展柜复用未入库角标并隐藏佩戴头像。展柜库存状态对当前已提交账号只读精确有序匹配，显式副本及脱库快照排除，匹配用于显示；入库仍由确认动作提交。

角色、配置、圣遗物、组合、队伍和项目中的可操作卡片共用 `styles/action-cards.css`。用 `data-card-action` 声明详情、选择或替换。详情触发区悬停、按下及键盘聚焦时，仅上边缘变绿，角色卡保持原位。选择弹窗内的候选卡与替换入口使用蓝色反馈。有效属性由父组件显式提供，配置/组合紧凑文字按火深色高亮，库存主页按普通词条显示。主词条名称在筛选中用全称，卡片元素伤害用既定简称。

圣遗物详情复用1000px编辑器与112px图片，名称、部位、套装只读，别名可编辑。强化、主词条和四个固定副词条槽使用共用表单，单位列稳定对齐；强化记录、推定及手选分别标来源。另存新ID、独立别名及推定，原件、库存引用、来源身份和观测历史各自保持。

手动新建先选套装与部位，后续复用详情表单，内容最大640px。预览自动生成名称，返回保留草稿，确认后建立实物。套装空置校验标红并聚焦。部位与属性选择复用共同图标和控件。

收藏使用 FavoriteControl 和 FavoriteMark 的扁平三瓣三角，28/32px，0 至 3 级按上、左下、右下填充。详情按钮循环切换等级。圣遗物与组合的右键收藏开关首次设为一级，再次操作清除收藏。物品按账号与实体 ID 保存，组合和队伍按记录保存。角色卡与首选配置共用一个收藏等级，各备选配置独立收藏。历史角色收藏与首选收藏等级不同时取较高值。更换首选时，每套配置保留自己的等级，角色卡随新首选更新。角色卡右上角只在已收藏时显示收藏标记。配置卡和队伍卡在标题行右侧显示已收藏标记，列表可多选收藏等级或按等级升降序排列。另存的配置、物品、组合和队伍从未收藏开始，收藏不参与内容去重。

删除库存清除实物身份，穿戴、配置和组合保留数值及inventoryId:null的脱库快照，内部记录键独立生成。再次应用通过明确入库或替换完成。只读展柜快照保留原内容，库存变化重新决定其持有显示。

组合普通新建按装备、有效属性、参考角色与冻结基准去重；显式另存总是保留原件并新建记录。编辑弹窗的删除按钮先确认，再删除选定的组合记录及其草稿。角色“应用组合”只更新草稿；缺部位仍确认卸下。共享物品的其他角色引用保持。

角色、配置与组合内嵌ComparisonPanel/LoadoutComparison，选择后原地显示两侧统计、差值和五部位内容，窄屏按部位配对。选择与结束比较属于查看动作，各侧统计基准保持独立。有效属性、白值与自动命名见[统计口径](#圣遗物统计口径)。

角色、组合及计算候选的圣遗物占用槽，点图标替换，点正文或卡片空白处查看，空槽点选装备。悬停、按下或用键盘聚焦圣遗物、武器和队员的替换区时，`CardReplaceMark` 在图片和角标上方显示蓝色遮层。双箭头在整个替换区居中，图形上下贴合 SVG 边界。在详情区执行相同操作时仅卡片上边缘变绿。只读展柜整卡查看，可从详情点「入库」并确认。替换弹窗提供「卸下」，桌面也可使用右键及 Shift+F10 快捷菜单。圣遗物的角色、角色配置与组合引用，以及队伍查看来源配置，共用最近五个返回点。继续跳转时加入最新返回点，超出容量则移出最早的一点，未保存草稿沿用退出确认。关闭当前引用详情或按 Esc 逐层返回，复原来处的搜索、分页、滚动、焦点和编辑草稿。普通装备、选择和确认弹窗按原层次关闭。

### 导入、退出与装饰

手动添加的角色目录、展柜和 Mona 导入共用 920px 内容宽、固定底栏和 40px 动作。手动选角复用完整目录、工具栏与默认排序。选定角色后进入与库共用的角色详情编辑器，可编辑培养、武器和五个圣遗物槽，应用组合或调整有效词条。武器可留空或在武器选择框里卸下。展开角色面板后，等级、突破、命座、武器和圣遗物取自当前草稿并即时求值。空槽只计入角色自身的基础攻击力。点「还原」恢复已保存的面板，点「保存」才写入库中。返回角色目录时保留搜索和筛选。在手动添加的详情中修改圣遗物字段时，物品修改先保存在角色草稿。保存角色一次提交培养、穿戴和物品修改，放弃草稿保留原账号资料。Mona 与 Enka 的确认和合并见[导入协议](#外部导入协议)。

未保存退出三项动作为保存深绿、继续编辑浅绿、放弃红色。成功保存后继续关闭/返回/切换，失败留草稿。应用内退出键由dialog处理，浏览器刷新/关闭使用原生保护。

Line凯尔特三角用于圣遗物库，组合版叠交织内圆与完整外圆；Ribbon保留独立变体。关闭图为两根相同双头箭重叠的方形外缘，32px按钮、20px火色图标，箭杆2.2。页角采用已选藤结，四库面板各角40px、内缩7px、透明度.32，其他既有页角25px。分隔装饰已退出，装饰让出点击。

## 外部导入协议

导入事务和共享引用的通用规则见[文件规范](../../docs/files-and-state.md)。实际录存见[验证资料](../../tools/data/README.md#验证资料与独立计算记录)。

### Enka公开展柜

协议依据为 https://github.com/EnkaNetwork/API-docs/blob/master/api.md 及其docs/gi/api.md。固定元数据采用 `b94bc40528941126590e0eefb0f03278e7a44ec8`，目录与补充顺序在tools/data/sources/catalog/enka。网络契约公开入口为 `@leyline/schema/enka`。

UID为9至10位数字。桌面通过固定主机IPC查询，网页开发和本地预览提供同源/api/enka/:uid，子路径按应用base处理；静态托管需配置同源通道。查询使用自定义User-Agent，按服务TTL缓存，合并同UID进行中请求，上限16个UID；响应上限2MiB，超时15秒。取消中止网页请求或丢弃桌面迟到结果，400/404/424/429及服务异常就近反馈。

账号可保存或清空UID，弹窗默认带入。确认导入后绑定UID，查询或取消保持原绑定；绑定与请求不一致时通过账号信息或账号切换处理。修改UID使原预览失效。

培养、突破、命座、基础天赋、武器及装备采用响应值，战斗面板fightPropMap由适配器忽略。新建手动角色的满级默认仅属于创建表单。

新增或待补全角色默认勾选，完整本地角色默认不选；确认前复核账号、所选角色及库存。确认默认导入并合并，可切换仅快照；完成后留角色库并清除遮挡结果的筛选。

合并逐项核对套装、部位、星级、强化、主属性和值、有序副词条。优先匹配默认原件，显式副本和脱库快照排除；复用已有库存 ID 和别名。比较时消除百分数换算的浮点尾差，主词条按该星级和等级的档位核对游戏显示值。副词条顺序及有意义的精度参与匹配。核验历史只更新强化次数，保留本地原始数值。展柜详情沿匹配的实物 ID 查询角色、配置与组合引用，展柜自身仍保存原快照 ID。确认后完整替换所选角色五部位本地引用，缺槽清空；旧库存、其他角色及保存配置/组合保留。

仅快照保留showcase快照身份，详情的单件入库只操作该件库存。展柜“保存组合”先打开未保存草稿，编辑器保存时才处理缺件入库确认；取消保留原库存。相同组合打开已有记录。预览后发生相关修改时拒绝陈旧提交。

角色等级按当前Build接受1至90、95、100，武器及装备按正式目录与合法性校验，圣遗物实物接受四星和五星，按各自强化上限、主词条表及套装星级/部位校验。男女旅行者、男女奇偶的七种元素形态按展柜的角色和形态编号共同识别。四个无元素基础形态均只有普通攻击，当前培养格式要求普攻、战技、爆发三项等级，预览会说明限制并继续导入其他角色。遇到未知形态时，预览显示收到的形态编号。

普通角色与元素旅行者的天赋编号采用固定版 Enka 目录或 GachaBase 正式发布页。发布页编号逐项匹配固定版 genshin-db 的英文普攻、战技、爆发名称，来源记录于 [skill-supplements.json](../../tools/data/sources/catalog/enka/skill-supplements.json)。奇偶各形态和无元素旅行者的技能顺序取自[技能组原表](../../tools/data/sources/character-text/base-and-manekin.json)。全目录导入测试逐个检查角色身份、形态和天赋顺序，真实展柜回归另行核对原始培养及装备。

### Mona库存

Mona适配读取套装、部位、星级、强化、主副词条及来源身份，equippedBy作为穿戴备注。当前确认流程导入实际库存，角色与独立组合由各自显式动作创建。

文件与JSON粘贴共用预览，提供新增、已存在、跳过、冲突及搜索，每页6件。记录上限10000，文件入口按实际格式校验。已有内容默认保留，更新由明确选择提交，冲突阻止更新。

社区别名与中文身份采用固定目录。对已有导入身份的补全先核对原指纹及整件快照，经确认只更新内容保持的条目；手动改过的内容保留待核对状态。源ID及其原始备注保留，无ID重复实物按现有出现顺序区分。

普通生成和检查使用已采用canonical，`--capture`显式读取参考源。来源版本与具体身份核对见[参考项目](../../tools/data/README.md#参考项目与资料入口)。

### 显示与强化

formatGameStat按游戏精度生成文本：比例一位小数与百分号，固定生命、攻击、防御和精通为整数，保存值保持原精度。名称使用属性名，单位由数值与图标表达；编辑选项按固定/比例区分。

强化次数为首次条目之后的重复提升次数。初始三词条在+4获得第四条时记首次出现。Enka appendPropIdList经编号、稀有度和显示汇总核验后写入rolls，显示rolls−1。

缺记录时按实际等级、显示舍入和自身星级的初始条数枚举联合合法历史，四星初始二/三条，五星初始三/四条。满级五星重复命中合计4或5，优先选择总数较小的合法解，再按副词条顺序选择较小项。无合法解显示问号。悬停区分showcase记录、inferred推定与manual选择；修改实值或等级清除失效历史。

历史保存于substats.rolls及rollSource，rolls包含首次条目。比较装备内容使用实值和有序词条，来源及历史元数据单独比较。精确合并保留本地ID和别名，核验过的展柜记录优先于推定，同步内容保持的引用。

### 平均条数与有效条数

平均条数为“保存副词条值÷同稀有度四档单次值的算术平均”，包含首次条目，显示一位小数。

| 五星副词条 | 四档平均值 |
| --- | --- |
| 固定生命、攻击、防御 | 253.94、16.535、19.675 |
| 生命/攻击比例、防御比例 | 4.955%、6.195% |
| 暴击率、暴击伤害 | 3.305%、6.605% |
| 充能效率、元素精通 | 5.505%、19.815 |

档位来自 src/game-data/data/tables/artifact-rolls.json，采用LunaGC固定ReliquaryAffix的401/501组并与Enka身份交叉核对。Mona显示档位的生命/攻击平均4.975%、暴伤6.6%与该表精度不同；KQM的RV采用最高档归一化。三者按各自定义使用。

生命、攻击、防御的有效条数为 `(比例副词条合计 + 固定副词条合计 / 白值) / 对应比例单次平均值`，各件按自身稀有度计算。其他有效副词条按保存值除档位平均值。统计对象为副词条，白值来自角色成长/突破及武器基础攻击。

角色草稿与展柜使用各自配装白值。换武器或卸下时即时重算，空武器槽对攻击白值的贡献为零。独立组合保存创建时的基准、参考角色和武器；重选参考角色时采用匹配本地首选Build，缺完整参考时用默认生命14000、攻击750、防御700。默认攻击分解为角色230与武器520，来源在effective-roll-basis.json。

组合保存后保持所捕获基准，比较两侧分别使用各自提供的基准。应用到目标角色时其草稿统计使用目标角色口径；组合身份、保存名称和冻结分母保持独立。

### 有效属性与名称

默认有效属性源为miao-plugin `9d8972c2b060ede67d1b0dc7565abb4fe39b3aa7` 的artis-mark.js及各元素旅行者artis.js、奇偶calc.js mainAttr。采用有非零声明的属性组，来源及策略维护于character-effective-stats.json；用户覆盖按账号/角色保存。

编辑顺序为暴伤、暴击、精通、攻击、防御、生命、充能，后三类基础属性各合并固定与比例。只读时有效项排前。角色所有配置共用账号/角色设置；组合选参考时捕获设置，之后独立保存。

组合自动名按套装简称、沙杯冠主词条及有效条数一位小数组成。角色配置自动名共用套装简称和件数前缀，例如「4绝缘」和「2染血+2苍白」。套装简称由[正式表](../game-data/data/tables/artifact-set-short-names.json)提供，未登记使用全称。主词条简称为生、攻、防、精、充、暴、爆、治及元素/物理单字，缺部位如实显示。

普通新建以五部位实物ID、归一化有效属性、白值基准和参考角色去重；显式另存总是新建组合并保留原件。自动名随装备、有效属性和参考基准更新，手动名保存后保持，自动命名可切回；还原恢复完整草稿。
